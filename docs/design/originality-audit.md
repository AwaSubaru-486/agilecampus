# 原创性审计：原版指纹 vs V2 设计

日期：2026-09-20
对应计划：`docs/superpowers/plans/2026-09-20-agilecampus-original-product-and-ai-collaboration.md` §0.3

---

## 0. 两个参照物，不是一个

做这份审计时发现一个必须先讲清的事实：**「现在长什么样」和「老师原版长什么样」是两回事。**

| 参照物 | 是什么 | 怎么看 |
|---|---|---|
| **老师原版** | `upstream/master`（sdiver/agilecampus） | `git show upstream/master:<path>` |
| **本分支现状** | `feat/risk-aware-closure`，含 `feat/repository-composed-v2` 那批 UI 重做 | 工作区 |

原计划 §0.3 第一条把「取消永久左侧栏」列为与原版的差异，但**原版本来就是顶部导航**：

```tsx
// upstream/master:src/app/(app)/layout.tsx
<header className="sticky top-0 z-20 flex items-center justify-between border-b ...">
  <nav className="flex items-center gap-1">   // 三个链接，横向
<div className="mx-auto max-w-5xl p-6">{children}</div>
```

那个左侧栏来自**你自己 fork 时的 UI 重做**（`feat/composed-original-ui`、`feat/human-centered-workspace`），本分支继承了它。

这不影响结论，但影响判据：**六项指纹要分别对照两个参照物**，否则会出现「以为在摆脱老师，其实在摆脱自己」的错位。下文每一行都标注是拿谁比的。

## 1. 登录页

| | |
|---|---|
| **原版指纹** | `(auth)/login` 单卡居中，邮箱口令 + 飞书按钮 |
| **本分支现状** | 未改动，与原版一致 |
| **V2 设计** | 保持单卡，但换 V2 token；补一条「这个产品是干什么的」一句话 |
| **为什么不同** | 结构上**不追求不同**——登录页没有设计空间，强行原创是浪费 |

> 判定：登录页不计入六项原创判定。计划 §0.3 把它列进截图对比，但它不该成为差异来源。

## 2. 项目列表 / 项目入口

| | |
|---|---|
| **原版指纹** | `/projects` 是「所有项目」标题 + 卡片网格，每卡显示团队名、进度条、状态徽章（`max-w-3xl`） |
| **本分支现状** | 卡片网格 + 顶部四个指标（进行中项目数 / 整体完成率 / 剩余任务） |
| **V2 设计** | `/today` 成为登录后默认入口：**跨项目行动队列**（待回应 / 待验收 / 求助邀请 / 被退回 / 逾期）。`/projects` 退为「项目脉搏」——最近访问 + 每项目一句话状态，不再是卡片网格 |
| **为什么不同** | 原版问「有哪些项目」，V2 问「**现在该我做什么**」。这是从「浏览」到「行动」的转变，不是同一张网格换皮肤 |

---

## 3. 项目主页

| | |
|---|---|
| **原版指纹** | `max-w-5xl` 纵向：`<h1>项目名</h1>` → 描述 → **唯一一个 `<section>`：`<h2>看板</h2>`**。极简到几乎没有页面 |
| **本分支现状** | 纵向堆叠七段：概览卡+进度 → 工作现场（正在发生/接力/里程碑）→ 健康度 → 求助条 → 新建任务+筛选+看板 → 项目档案 → AI 对话 |
| **V2 设计** | **四个互斥工作模式**（`?space=`）：现场 / 工作 / 协同室 / 记录。一次只渲染一个，不纵向堆叠 |
| **为什么不同** | 原版只有「看板」一种视角；本分支是「什么都往下堆」的长页面。V2 承认**同一个项目要看的东西有四种性质**（谁在动 / 怎么流转 / 在探索什么 / 留下了什么），各自需要独立的画布，而不是叠在一页里 |

---

## 4. 看板与任务操作

### 4.1 看板

| | |
|---|---|
| **原版指纹** | 三列（todo / doing / done），列内卡片直接展开编辑表单；拖拽改状态 |
| **本分支现状** | 三列变四列（加了「待验收」），卡片上直接展开富表单；另有四维度分组与标签筛选 |
| **V2 设计** | 仍是四列固定语义（待开始 / 进行中 / 待验收 / 已完成），但**不允许用户自定义状态**；列头显示数量与 WIP 提示；列底快速新增只收标题 |
| **为什么不同** | 原版把「任务状态」当可配置项，V2 把它当作**产品立场**——四档是「学生不能自证完成」这条规则的界面体现，不该让人改掉 |

### 4.2 任务操作

| | |
|---|---|
| **原版指纹** | 卡片内直接展开编辑表单 |
| **本分支现状** | 卡片内展开更大的表单（目标、承诺、验收、标签、依赖全塞进去），另有 `?task=` 深链打开的 `EditModal`——**同一件事有两个入口** |
| **V2 设计** | **卡片只用于扫描**（标题、负责人、截止、一个流程信号、最多两个标签）。完整动作在右侧**任务抽屉**（`?task=`）完成，抽屉分八段：目标 / 交接 / 执行 / 证据 / 验收 / 关系 / 历史 / AI |
| **为什么不同** | 本分支的卡片已经膨胀到「卡里能开一个弹窗里的表单」，且卡片表单与 `EditModal` 功能重叠。V2 把扫描与操作分开：卡片回答「要不要管它」，抽屉回答「怎么管」 |

## 5. AI 协作

| | |
|---|---|
| **原版指纹** | `chat-panel.tsx`：单会话平铺聊天框，AI 写工具产出草案卡片，确认后落库 |
| **本分支现状** | 会话列表 + 可见范围 + 从任意回复分叉 + 草稿卡片（仅前端内存态，刷新即失） |
| **V2 设计** | **协同室**：三栏（探索树 / 工作台 / 上下文与待确认）。会话是**树**不是列表；**上下文包**可见可冻结；AI 动作进**待确认池**（持久化、跨会话集中）；可**并行比较**两个分支并形成**决策记录** |
| **为什么不同** | 原版与现状都是「聊天框 + 在里面点确认」。V2 把 AI 协作拆成五个可审计的对象：上下文包 → 方案 → 决策 → 待确认 → 证据。**AI 从对话框里的助手变成有交接协议的成员** |

---

## 5.5 团队与成员页

| | |
|---|---|
| **原版指纹** | `/teams` 是「我的团队」+ 卡片列表；成员、标签、资源各占一个子页；无 AI 成员概念 |
| **本分支现状** | 同上，另加 `/teams/[teamId]/agents`（AI 成员注册与管理） |
| **V2 设计** | `/teams` **退出一级导航**，团队与 AI 成员管理收进项目切换器里的「团队设置」。成员页与 AI 成员页并列，用 §3.3 的人机语义色区分 |
| **为什么不同** | 原版把「团队」当成与项目平级的浏览对象；V2 认为**团队是项目的背景**，不是每天要看的东西——每天要看的是「今天该我做什么」 |

## 6. 视觉语言

| | |
|---|---|
| **原版指纹** | 亮蓝主色 `#315cf5`、白底、`ac-card` 圆角卡片堆叠、英文眉题（`WORKSPACE` / `EXECUTION`） |
| **本分支现状** | 同上，且更重：左侧栏、更大圆角、更多彩色徽章 |
| **V2 设计** | 暖灰底 `#f3f1eb` + 纸感面板、**人为绿 / Agent 为紫**的语义色、圆角降到 12/16px、阴影只用于浮层、**禁用装饰性英文眉题** |
| **为什么不同** | 不只是换色。关键是引入了**人机语义色**——原版没有「谁是人、谁是 AI」这个概念，因为原版没有 AI 成员 |

## 7. 六项判定汇总

计划 §0.3 要求六项全部不同。逐项对账：

| # | 判定项 | 对照谁 | V2 是否不同 | 由哪个 Commit 落地 |
|---|---|---|---|---|
| 1 | 全局导航 | ☑ 两个都不同 | 是——顶部工作带 + 项目切换器 | Commit 2 |
| 2 | 项目入口 | 原版 | 是——`/today` 行动队列 | Commit 4 |
| 3 | 项目主页 | 原版 | 是——四模式互斥 | Commit 3 |
| 4 | 任务操作 | 原版 | 是——扫描与操作分离进抽屉 | Commit 5 |
| 5 | AI 模型 | 原版 | 是——上下文包/决策/待确认/证据 | Commit 6–11 |
| 6 | 视觉语言 | 原版 | 是——新 token + 人机语义色 | Commit 2 |

**注**：第 1 项若只论「与原版的差异」，原版本就是顶部导航，谈不上不同；真正的差异是**顶部工作带 + 项目切换器**这套新骨架，以及摆脱**自己 fork 那版的左侧栏**。这一条在 Commit 13 的回归检查里要特别留意——别对着错的人证明自己。

## 8. 不做「故意改名」这种假原创

计划 §0.3 明文禁止靠改名冒充原创。此处补充三条自律：

1. **不隐藏来源。** 本仓库是 `sdiver/agilecampus` 的 fork，`upstream` remote 与 LICENSE 原样保留。
2. **借鉴的非平凡代码按许可证署名**，见 `THIRD_PARTY_NOTICES.md`。
3. **不改产品名充当原创。** 「AgileCampus」这个名字继续用——原创来自重新设计的产品结构与交互对象，不来自换一个名字。名字是老师的，设计是我们的，两件事分开说清楚，比含混过去诚实。
