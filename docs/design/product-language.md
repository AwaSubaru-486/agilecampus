# 产品语言：术语、路由与骨架

日期：2026-09-20
状态：**冻结**。本文件定下的名称与路由，后续 Commit 不得擅自改动；要改先改这里。

---

## 1. 产品主张

> **AgileCampus 不替学生做项目，而是让团队在人与 AI 之间交接工作时，不丢背景、不丢责任、不丢证据。**

一句话解释它和普通项目管理工具的区别：

- 普通工具问「有哪些任务、各在什么状态」
- AgileCampus 问「**这件事现在停在谁手上、他为什么要接着做、做完了谁认账**」

---

## 2. 五个核心对象

界面围绕这五个对象组织，**不再围绕「仪表盘 / 看板 / 聊天」组织**。这五个词是全产品的公分母，界面文案、代码命名、API 路径一律用它们。

| 对象 | 回答的问题 | 已有数据 | V2 新增能力 |
|---|---|---|---|
| **行动** Action | 现在该我做什么？ | task / review / blocker | 角色化行动队列 |
| **交接** Handoff | 这件事谁接住了？ | assignment / commitment / activity | 交接契约与回应时限 |
| **上下文** Context | AI 或同伴需要知道什么？ | task / conversation / messages | 可见、可裁剪、可冻结的上下文包 |
| **决策** Decision | 为什么最后选了这个？ | conversation / activity | 方案比较与决策记录 |
| **证据** Evidence | 做成了什么，凭什么算数？ | completionNote / entry / activity | 证据包与来源链 |

## 3. 术语表

**一个概念只用一个词。** 下面的「不要用」一列，是此前各版文档与界面里出现过的同义说法——它们必须消失。

| 用 | 不要用 | 说明 |
|---|---|---|
| 行动 | 待办、todo、事项 | 行动带主语与紧迫度，不只是「一条没做完的事」 |
| 交接 | 指派、分配、派活 | 「指派」只描述动作，「交接」包含契约与回应 |
| 接住 / 接不住 | 认领、接受、拒绝 | 口语、对称，且「接不住」不是失败 |
| 卡住 | 阻塞、blocked | 界面上说人话 |
| 概览 | 现场、dashboard、工作台 | 项目四模式之一 |
| Agent | 聊天、AI 助手、会话、协同室 | 它是人和 Agent 一起推进任务的工作区，不是聊天页 |
| 成果 | 记录、档案、复盘 | 项目四模式之一 |
| 上下文包 | 快照、prompt context | 「包」强调它是个可查看、可冻结的物件 |
| 证据 | 完成说明、附件 | 证据要回答「凭什么算数」 |
| 待确认动作 | 草案卡、draft | 它现在是一个持久、跨会话的对象 |
| 承诺 | commitment note | 界面上一律说「你打算怎么做」 |
| AI 成员 | 机器人、agent（裸用） | 首次出现写「AI 成员」，其后「AI」或名字 |
| 里程碑 | 节点、阶段 | 保留「里程碑」，老师认可这个词 |

**关于「任务」**：保留。它是最底层、最没有歧义的工作单元。五个对象是**看它的五种角度**，不是五个新实体。

## 4. 全局路由

一级导航三项，**桌面横向排布在顶部工作带，不做永久左侧栏**。低频入口（资料库、设置）收进账户菜单，避免首次使用时把配置和行动混在一起。

| 路由 | 名称 | 职责 |
|---|---|---|
| `/today` | 今日 | 当前用户跨项目的行动队列 |
| `/projects` | 项目 | 项目脉搏、最近访问、归档 |
| `/collaboration` | 协作中心 | 求助邀请、待确认的 AI 动作、AI 成员状态 |
| `/library` | 资料库 | 跨项目成果、文档、可复用上下文（账户菜单） |
| `/settings` | 设置 | 账户、连接、令牌、通知（账户菜单） |

### 兼容策略

旧路由**保留重定向一版**，不直接删除：

- `/health` → 不再是一级导航，风险进入 `/today` 与项目「现场」
- `/teams` → 不再是一级导航，团队与 AI 成员管理进入项目切换器里的「团队设置」
- `/settings/tokens` → 保留深链接，在 `/settings` 内做子页
- 新路由未完成前，旧路由不动

## 5. 项目四模式

```text
/projects/:projectId?space=live      概览     项目进展、风险与当前接力
/projects/:projectId?space=work      任务     任务如何拆分、交接与验收
/projects/:projectId?space=studio    Agent    人和 Agent 一起推进任务
/projects/:projectId?space=record    成果     已交付成果、决策与证据
```

| 参数 | 主对象 | 对应旧页面的哪部分 |
|---|---|---|
| `live` | 行动 + 交接 | 工作现场 + 健康度 + 求助条 |
| `work` | 任务 + 里程碑 | 看板 + 筛选 + 时间线 |
| `studio` | 上下文 + 决策 | AI 对话面板 |
| `record` | 证据 + 档案 | 项目档案 + 复盘 + 活动流 |

### 规则

1. 缺省 `space` 为 `live`。
2. **四种模式一次只渲染一个**，不纵向堆叠——这是与原版最根本的差别（原版项目页只有一个看板，本分支是七段堆叠；V2 既不堆叠也不只有一块）。
3. `task=<uuid>` 打开全局任务抽屉，可叠加在任意模式之上。
4. `conversation=<uuid>` 只在 `studio` 生效；其他模式遇到它时跳转过去。
5. `action=<uuid>` 用于定位一条待确认动作。
6. **所有筛选写进 URL**，可复制、可刷新、可前进后退。

## 6. 应用骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ AC  [项目切换器⌄]   今日  项目  协作中心              头像 │  56px 顶部工作带
├──────────────────────────────────────────────────────────────┤
│ 项目名称 / 最近里程碑         [概览][任务][Agent][成果] [＋] │  项目上下文带
├──────────────────────────────────────────────────────────────┤
│                       当前模式主画布                          │
├──────────────────────────────────────────────┬───────────────┤
│ 状态与同步提示                                 │ 可选上下文抽屉 │
└──────────────────────────────────────────────┴───────────────┘
```

固定尺寸（避免各页各写一套）：

| 元素 | 尺寸 |
|---|---|
| 顶部工作带 | 桌面 56px / 移动 52px |
| 项目上下文带 | 桌面 sticky 48px，仅项目内出现 |
| 上下文抽屉 | 桌面 420px / 移动全屏 sheet |
| 页面最大宽度 | 现场 1280 / 工作看板不限 / 协同室 1440 / 记录 1120 |
| 控件高度 | 小 28 / 标准 36 / 主要 40 |

## 7. 语言规则（写作与界面文案）

1. **说人话，不说系统话。** 「你卡住了」而不是「任务状态：阻塞」。
2. **禁用装饰性英文眉题。** `WORKSPACE`、`EXECUTION`、`CONTEXT LAB` 一律删——它们不携带信息，只制造「像专业软件」的错觉。
3. **状态不能只靠颜色。** 每个色块旁边必须有一句短文本。
4. **一个屏幕最多一个高强调动作。** 到处都是主按钮等于没有主按钮。
5. **错误文案要给出下一步。** 「样本量不够，补到 100 份」而不是「操作失败」。
6. **不把 AI 的输出写成学生本人的成果。** 凡是 AI 做的，界面上必须能看出来是 AI 做的。

## 8. 人机语义色

原版没有「谁是人、谁是 AI」这个概念——因为它没有 AI 成员。V2 把它提升为一等语义：

| 语义 | 色 | 用处 |
|---|---|---|
| 人 | 绿 `--color-human` | 人的行动、人的发言、人的产出 |
| AI | 紫 `--color-agent` | AI 成员的行动、发言、产出 |
| 信号 | 蓝 `--color-signal` | 需要人注意但不分人机的交互态 |
| 风险 | 红 `--color-risk` | 逾期、卡住、退回 |
| 提醒 | 橙 `--color-warn` | 临期、待确认 |

**人与 AI 是并列的两类成员，不是「正常 vs 警告」的关系。** 绿色不代表好人，紫色不代表危险——它们只是两种身份。
