# AgileCampus 会话记忆与 Agent 接续：项目说明和小组分工

日期：2026-10-05。用途：给项目组成员说明产品主线、当前实现边界和下一阶段责任划分。

## 1. 一句话讲清楚我们在做什么

AgileCampus 面向多人一起开发的项目团队。它让人和 Agent 围绕同一项任务协作，并把 Agent 的工作背景、代码基线、已做决定、失败尝试和待办事项整理成可检查、可交接的材料。一个 Agent 或开发者停下来后，另一个人可以在自己的工作区核对材料，再让自己的 Agent 接着做。

我们做的不是把聊天窗口搬进项目管理网页，也不只是让 AI 自动写任务或自动合并代码。核心问题是：**代码工作可以由人和 Agent 并行推进，但当任务换人、会话中断或方案分叉时，工作上下文怎样有出处地保存、怎样交给指定接手者、怎样确认对方真的接上了。**

## 2. 用一个实际场景理解主线

假设成员 A 在 VS Code 中用 Codex 做“修复登录回调”任务。A 和 Agent 已经确认了复现条件、改过几处代码、试过一个失败方案，并留下尚未完成的测试。A 下线后，成员 B 需要接手。

系统应支持这条路径：

```text
A 的本机会话产生事件
        ↓
按任务和会话绑定，保存有序、不可变的来源记录
        ↓
冻结一次整理范围：任务版本、会话序号、事件出处、Git 基线和缺口
        ↓
AI 根据固定范围提炼接手草稿；每条结论能回到对应来源
        ↓
A 检查并修订草稿，明确选择接收人和发布版本
        ↓
B 在自己的账号和工作区取得这个版本
        ↓
B 核对仓库、分支和 SHA，必要时创建独立 worktree
        ↓
B 启动自己的 Agent，并把已接受的记忆作为明确上下文
        ↓
B 的新工作继续产生记录，完成后由人验收
```

AI 的任务是帮助整理、检索和继续执行；项目目标、交接对象、方案选择、代码合并和成果验收仍由人负责。系统应准确显示各阶段状态，不能把“本机已记录”“草稿已生成”“已发布”“对方已接收”“Agent 已继续”合并成一个含糊的成功提示。

## 3. 必须区分的三种材料

| 材料 | 里面是什么 | 解决什么问题 |
|---|---|---|
| 会话事件（Event） | Hook 实际收到的用户输入、工具调用/结果、停止事件等，有序、带来源标识 | 说明哪些内容确实被采集到了 |
| 接手记忆（Memory） | 目标、约束、已完成、未完成、决定、失败原因、阻塞、下一步和证据引用 | 让人或新 Agent 快速恢复工作背景 |
| 交接包（Package） | 某个记忆版本、来源范围、任务版本、仓库身份、Git SHA、完整性与分享信息 | 让指定接收者拿到同一份、可核对的交接材料 |

这三者不能互相冒充。模型说“测试通过”不等于测试确实运行；Hook 没收到的对话不能凭空补成完整记录；摘要不是完整 transcript；下载成功也不等于 Agent 已经续做。

我们传递的是经过人检查的明确材料，**不承诺复制 Codex、Claude 等供应商的私有 session 状态、隐藏推理或任意 IDE 对话**。每个来源适配器必须说明支持范围和缺口。

## 4. 断点接班和并行尝试的关系

断点接班是一条工作从 A 转给 B：B 取得一个确定版本的记忆和代码基线后，继续同一目标。

并行尝试是从同一个检查点分出多个工作线：例如两个 Agent 在各自独立 worktree 中尝试不同修复。每条尝试都有自己的 `attemptId`、分支、`baseSha` 和会话来源；团队比较结果与差异后，由人决定采用哪条方案或如何合并。

两者共用同一套基础信息：任务、记忆版本、来源、代码基线和责任人。它们不是让 AI 擅自替项目负责人选择需求，也不等于自动合并。当前仓库已有从检查点 SHA 建立独立 worktree 和比较尝试的代码基础；它还需要与新的会话记忆版本及接收流程接起来。

## 5. 目前做到了哪里

以下是仓库现状，不代表整条端到端链路已经完成：

- **本机会话记录基础已实现。** 扩展有本地绑定、不可变事件存储、Codex Hook 适配与记录查看；Hook 事件只在符合本机绑定的任务/会话时落盘，并有来源缺口和失败状态。
- **来源支持有边界。** 当前实现聚焦 Codex Hook。真实 Codex 配置是否已安装和信任、真实 Extension Host 是否能收到并显示事件，还需要在隔离环境里按计划实测。Claude 或任意 IDE 对话不能据此宣称已支持。
- **统一记忆格式和服务端基础已存在。** `shared/session-memory/` 有事件、记忆和交接包的类型/校验；数据库有会话、提炼作业和记忆草稿相关表；存在按项目权限读取会话/发布索引的基础。
- **旧检查点接力与 worktree 基础已存在。** 可以发布旧式检查点摘要、指定成员创建交接记录、预检并从检查点启动新会话；扩展还有从准确 SHA 创建隔离 worktree 和比较尝试的代码。它们不是新的“自动整理会话记忆并跨机器续接”闭环。
- **人和 Agent 身份基础已存在。** 数据模型能区分 `human` 与 `agent`，团队角色有 admin、teacher、student。下一步要核对并补齐这些身份对“生成、编辑、发布、查看和接收记忆”的权限，不应另造一套互相矛盾的身份概念。
- **仍待实现或证明。** 用真实来源冻结提炼输入、AI 生成有出处的记忆草稿、保护人工修改、将指定版本安全发布并供另一工作区取回、B 核对基线后启动自己的 Agent，以及 A→B 的真实接班演示。

此前扩展自动化测试和构建在多个代码批次中通过；它们主要证明合成事件与本地逻辑。最终汇报要重跑当时的命令，并把“自动化通过”和“真实 IDE/双工作区通过”分开记录。

## 6. 推荐的责任划分

按“你 + 负责 worktree 的组员 + 负责身份权限的组员 + 负责前端的组员”四条责任线安排。具体姓名由组内映射。每个人交付自己的可验收部分，不把一整条跨端链路压给一个人。

### A. 你：会话来源与记忆主线负责人

**你负责决定并守住核心语义，负责本机来源真实性和端到端验收；不需要独自编写所有服务端、worktree 和前端代码。**

具体工作：

1. 维护会话来源接入：扩展如何绑定任务/会话、哪些 Hook 事件可被采集、失败和缺口如何显示。先把当前 Codex 采集在隔离开发环境里实机走通；不在这一阶段承诺全模型通用。
2. 和后端组员冻结 `ExtractionInputV1` 与 `MemoryDocumentV1` 的语义：每项记忆包含什么、哪些事实必须有事件出处、什么条件只能标成 partial。
3. 提供预先写好答案的对话案例：目标后来改变、旧方案失败、Agent 口头称测试成功但没有工具证据、日志太长导致未处理范围等，用来验 AI 是否丢信息或编造。
4. 定义交接成功标准，主持 A→B 验收：同一材料版本、相同任务/仓库/SHA、B 能查出处、B 的 Agent 新会话确实拿到上下文并产生后续记录。

你不再同时承担服务端模型作业、全部身份授权、所有界面和 worktree 的实现。数据契约达成一致后，由各子系统负责人完成自己的实现和测试。

**交付物：** 接口字段和状态约定、来源覆盖说明、记忆质量用例、最终端到端验收报告。

### B. Worktree 组员：并行工作区与接收端负责人

**从仓库已有 worktree/attempt 能力继续做，不要从零重造 Git worktree。**

具体工作：

1. 盘点 `vscode-extension/src/git/worktree-service.ts`、`fork-attempt`、`resume-checkpoint` 和 `compare-attempts`，写明当前从检查点创建分支的已支持路径与限制。
2. 约定接收数据：`projectId`、`taskId`、`handoffId/checkpointId`、`memoryVersionId`、`attemptId`、repository identity、`baseSha`。本地绝对路径只留在该用户机器。
3. 接收后核对仓库身份、SHA、分支与尝试记录；不匹配时停止启动 Agent，说明具体原因。
4. 将已接受的交接记忆作为新 Agent 的显式启动上下文；记录 Agent 启动回执和新 session 关联。不能声称恢复了供应商的私有原生 session。
5. 并行尝试从同一个确定 SHA 创建不同 worktree，各自记录结果；展示差异给人选择。不自动安装依赖、不运行未知脚本、不自动合并。

**交付物：** 可重现的接收预检、worktree 和 attempt 关联、启动回执、并行方案比较演示与测试。

### C. 身份与服务端组员：权限、AI 提炼和记忆版本负责人

将已有的 `human/agent` 身份和 admin/teacher/student 团队角色用于真实授权，避免让 UI 自己判断权限。

具体工作：

1. 写权限矩阵，至少覆盖：谁能看事件索引、提交提炼、编辑自己的草稿、接受某版、发布给谁、接收什么、撤销分享。每个请求在服务端重新检查项目/任务成员关系。
2. 实现受控提炼接口：只接受冻结快照，服务端重新校验输入、权限和 `inputDigest`；用已有 `getModel()`，密钥留服务端。
3. 保存提炼作业和草稿版本，实现重复请求去重、超时/未知状态、明确错误；模型不可用时不能返回演示假结果。
4. 对模型结果验证字段、事件引用与来源范围。无法证明的内容标为 reported/unknown，不能由模型文字推断为已测试或已完成。
5. 实现草稿修订和发布记录的版本冲突保护。原始 transcript 与结构化记忆分开管理，不能把私人原文放入普通项目数据库或默认暴露给全组。

**交付物：** 权限矩阵、API/schema、幂等与冲突测试、模型输出证据验证、发布版本状态。与 A 共同确认共享 schema 后再写实现。

### D. 前端组员：真实流程界面负责人

先把当前主要使用的 VS Code 流程做清楚；后续再根据服务端接口接网页查看，不要一开始复制两套虚构流程。

具体工作：

1. 清楚展示本地 Hook 状态、来源范围、事件数量、缺口与最后更新时间。
2. 展示“本次整理将使用哪些记录、哪个任务版本、哪个 Git SHA”；用户冻结后这份快照不随新增事件漂移。
3. 展示 AI 生成的结构化草稿与出处，支持人工修改；明确显示本机保存、服务器草稿、已接受版本这几种状态。
4. 展示发布对象、记忆版本、接收状态；只有服务器确认后才显示“已发布/已接收”，Agent 启动必须等启动回执。
5. 接收端显示代码基线核对和 worktree 状态；无法匹配时提供可执行的修复/返回动作。
6. 界面只能调用真实 API 状态，不用 mock 数据冒充已连接；权限由服务端裁决，前端负责解释拒绝原因。

**交付物：** 按真实 API 接线的采集、预览、草稿/出处、发布和接收状态；空态/失败态；桌面与窄屏验收截图及操作路径。

## 7. 对接方式和避免互相踩代码

先用一个短的接口冻结会确定字段和状态，再并行实现：

```text
会话/记忆负责人：冻结事件范围、任务版本、代码 SHA、来源缺口
服务端负责人：验证并保存 memory draft / accepted version / publication
前端负责人：只消费已冻结的 API 和状态
worktree 负责人：使用 publication + baseSha 准备接收端并启动 Agent
会话/记忆负责人：验证 B 的 Agent 收到哪一个版本并继续
```

建议文件边界：

| 责任人 | 主要目录（签字冻结后） |
|---|---|
| 会话/记忆 | `vscode-extension/src/session-memory/**`、`shared/session-memory/**` 中经共同确认的事件/记忆契约、来源/质量文档 |
| Worktree | `vscode-extension/src/git/**`、`vscode-extension/src/commands/fork-attempt.ts` 与尝试比较/接收接线；改 `resume-checkpoint.ts` 前先与记忆负责人协调 |
| 身份/服务端 | `src/db/schema-session-memory.ts`、`src/lib/session-memory/**`、新增的 memory API 与对应授权/数据库测试 |
| 前端 | `vscode-extension/webview/**`、会话/记忆面板 UI；网页记忆页在 API 可用后再接，不修改服务端权限逻辑 |

`shared/session-memory/**` 是共同接口，任何人不能单方面改字段后要求其他人追着修。每个负责人维护自己模块的测试；最后由四方一起走集成场景。开始施工前必须检查现有未提交改动并登记文件边界，不覆盖队友改动。

## 8. 推荐实施顺序和每一关的验收

1. **接口冻结（半天内完成设计，不开始并行造 UI）**：签认事件范围、记忆字段、发布版本 ID、attempt ID、Git SHA、权限和状态。例子里说明 complete/partial 的区别。
2. **真实采集 + 冻结快照**：记忆负责人在隔离 Codex/VS Code 环境确认一条任务确实记录；预览冻结事件范围、任务和 SHA。采集或快照不通过就停在这里修。
3. **AI 草稿 + 人工编辑**：服务端处理冻结快照，草稿每条有证据引用；人工修改后重开仍在，重复提交不重复生成。
4. **指定对象发布 + 接收端准备**：权限服务创建特定版本；worktree 成员在另一独立工作区取回，核对代码和来源；不匹配时拒绝继续。
5. **完整 A→B→Agent 验收**：B 确认记忆和依据，启动自己的 Agent，确认启动上下文、sessionKey 和后续记录。之后再演示两个并行 worktree 的对比。

每道关卡由该模块负责人先交证据，整条链路由记忆负责人组织联验。出现缺口时记录 `BLOCKED` 和缺少的真实环境条件，不把 mock 或截图流程说成线上功能。

## 9. 组内汇报时可以这样讲

“我们把敏捷协作的重点放在人和 Agent 的接力上。现在仓库已经有任务/人/Agent 身份、Codex 本地会话事件记录、检查点交接和 worktree 并行尝试的基础。我们正在把它们接成一条可验证链路：从有出处的会话记录生成可编辑的接手记忆，经人确认后发给指定成员；对方在独立工作区核对代码基线，再让自己的 Agent 继续。项目不会把 AI 的说法当成验收，也不会把摘要或下载成功冒充完整接班。下一阶段的核心指标是：B 能否拿到同一版本、看到每条关键结论的出处，并让自己的 Agent 基于它产出可检查的后续工作。”
