## 1. 不允许改变的边界

- 不修改产品业务代码以使测试通过，不删除断言，不降低接续预检，不添加虚假回执。发现问题记入报告；修复另开工单。
- 可新增隔离测试脚本、合成 fixture、证据和报告；模拟仓库内可完成实际代码任务。
- 保留所有已有未提交改动，不自动提交或推送 AgileCampus 仓库。开始记录 HEAD、分支、dirty 文件和内容摘要，结束核对。若他人在测试时改动被测文件，标记受影响结果失效并重测，不能混用版本。
- 用户已允许建立 GitHub 模拟仓库；默认 private，仅上传本次合成代码和非敏感需求。不得将当前平台仓库改公开，不推真实会话、交接包、数据库、密钥或本机配置。
- 密钥从用户已配置的安全位置/本次安全输入取得；不要从历史聊天日志搜集，不在报告、shell 历史、命令参数、截图或仓库中明文写入。不要将 DeepSeek Key 当作平台 PAT。
- 仅向经核验的 DeepSeek 官方 HTTPS 地址发送 DeepSeek Key；故障代理使用假凭据，真实 API 流量不交给未知代理。
- 不覆盖用户全局 Codex 配置，不修改 HOME 或 CODEX_HOME，不全局降级 CLI，不使用跳过信任/审批/沙箱的危险参数。
- 本地 worktree 是文件隔离，不是安全沙箱。执行模型只获准处理模拟项目；测试环境不含真实项目、真实业务数据或无关凭据。
- 网络写入、PR 和合并仅限本次模拟仓库。不得让模型自行 push/merge；由执行者扮演审核者核对后执行。
- 测试库、模拟项目库、用户开发库三者必须分离。`tests/helpers.ts` 中的 resetDb 会 TRUNCATE，不能接用户开发库，也不能接保留演示链路的模拟项目库。
- 不声称“完整 session 原生恢复”：导出文本/结构化摘要后启动新 session 属于 context-only 接续。真实 session 捕获、摘要手填、原生恢复必须分开报告。

## 3. 环境与测试身份

### 3.1 一次运行一个 runId

格式 `YYYYMMDD-HHMMSS`，同一份报告全程使用同一个 runId。

- 本地工作根：通过 mktemp -d 创建并登记确切路径，不把临时目录建在产品源码内部。
- 平台被测副本：隔离复制当前被测源码和必要的未提交变更；不要复制 .env、node_modules、.next、真实聊天或认证资料。保存纳入的 dirty 差异 hash，以说明测的不是纯 HEAD。
- 平台模拟库：`ac_sim_<runId数字>`，只有本次合成用户与项目。
- 自动测试库：`ac_test_<runId数字>`，允许测试清空；专用 DB 角色只获准访问本次测试库。
- 平台端口：优先 3100；占用时选择空闲端口，记录到 manifest；不停止用户 3000 上的服务。
- A、B 的代码各一份独立 Git clone，不共享 .git、VS Code globalStorage、SecretStorage 或浏览器 Cookie。
- Reviewer、A、B、Outsider 四个真实平台账号。Reviewer 建团队，A/B 加入；Outsider 不加入。账号邮箱使用 runId 加 `.test` 域，密码单独保存在本次私密配置。
- 四个隔离浏览器配置或可证明独立的浏览器上下文；A/B 各一个独立 VS Code user-data-dir 和 extensions-dir。
- 一台机器模拟不同成员要写清楚“跨配置/跨 clone 实验”，不能写成已验证跨物理设备。

### 3.2 启动前强制检查

1. 记录 node/npm/git/gh/code/codex/entire 实际版本及可用性；版本不满足产品限制时记录 BLOCKED，不篡改版本检查。
2. 验证 GitHub 当前身份，只记录登录名；不要打印 token。拟创建仓库 owner 必须等于用户实际登录身份，不能猜用户名。
3. 建立专用数据库并只输出非敏感库名，连接后查询 current_database 验证；确认模拟库与自动测试库不同。确认专用角色无法连接用户开发库后，才允许运行 resetDb。
4. 检查被测副本 dotenv 加载顺序，在子进程内注入正确 DATABASE_URL，避免 .env.local 或 .env.test 把连接覆盖。验证数据库真实身份，不能仅看变量名。
5. Secret 环境单独注入，不使用 `env`/`printenv` 整体输出；自动测试进程剔除 DeepSeek Key，付费步骤单独开启。
6. 平台副本按 package-lock 安装，专用库应用 schema；启动命令在该副本执行 `npm run dev -- --port <已选端口>`。根据实际认证配置设置本次 origin，浏览器完成真实注册/登录。不能拿开发环境 Cookie 顶替。
7. 扩展在副本内构建。现有 F5 launch 会打开平台仓库父目录，不适合本实验：使用经本机 code --help 核实的 --user-data-dir、--extensions-dir、--extensionDevelopmentPath 和模拟 clone 路径启动独立开发宿主；确认打开的是模拟代码仓库。
8. 扩展设置 agileCampus.baseUrl 为本次平台地址；A/B 各用自己平台账号创建的 PAT 连接，PAT 只进 SecretStorage。

任何数据库隔离、密钥隔离或目标仓库检查失败，立即暂停相关写入，并报告明确前置条件。其余安全、独立的只读检查可继续。

### 3.3 API 成本与有限重试

- 先小请求验证官方端点，再进入真实产品调用；记录请求模型、返回模型、usage、耗时、finishReason，不保存授权头。
- 网页活体测试最多发起 8 个用户回合；模型编排可能一回合多请求，逐次统计实际 usage，不能把 8 回合说成 8 个 API 请求。
- 本地 Agent 最多 5 次正常启动：A 初始开发、B 接班、并行 X、并行 Y、必要的一次受控恢复。单次最多观察 5 分钟，总观察上限 25 分钟；超时通过正常停止方式结束本次拥有的进程。没有安全停止手段时不得启动长任务。
- CLI 的内部请求/令牌上限不能仅靠提示词保证；没有实际限额机制就报告“时间和启动次数受限，费用无硬上限”。可用供应商预算限制时先设本次预算；需要扩大调用量时停下询问。
- 网络瞬态失败最多原请求重试一次；400/401/余额不足不循环。重试写入复用同一幂等键，记录总次数。

## 4. 模拟项目：团队任务排期器

GitHub 仓库名 `agilecampus-sim-<runId>`，默认 private。先查重，创建后记录完整 owner/repo、URL、默认分支。仓库已存在且不是本次创建时禁止复用写入。

目标：完成一个小型 TypeScript 任务排期模块；不用业务 UI、不引入数据库或联网服务，避免模型把时间花在搭架子上。

### 4.1 冻结需求

导出 `rankTasks(tasks, now)`，输入任务含 id、priority（1/2/3）、deadline（ISO UTC 或 null）、status（todo/doing/done）。返回去掉 done 后的任务 id 数组。

规则：逾期任务优先；同组 priority 数字小者优先；同优先级 deadline 早者优先，null 最后；完全同分保持原输入顺序。deadline 等于 now 不算逾期。id 重复、日期非法、枚举非法必须明确抛错，不能静默丢弃。

固定 now 为 `2026-10-02T12:00:00Z`，不使用机器当前时间：

| id | priority | deadline | status |
| --- | --- | --- | --- |
| A | 2 | 2026-10-01T12:00:00Z | todo |
| B | 1 | 2026-10-03T12:00:00Z | doing |
| C | 1 | null | todo |
| D | 3 | 2026-09-30T12:00:00Z | todo |
| E | 1 | 2026-10-01T12:00:00Z | done |
| F | 1 | 2026-10-03T12:00:00Z | todo |

主样例期望 `A,D,B,F,C`。另至少覆盖：空数组、全部完成、deadline==now、null、同分稳定顺序、重复 id、非法日期、非法枚举、输入不被修改（深冻结输入测试）。

隐藏验收样例仍遵循上述公开需求，不增加未告知模型的新规则。由 Luna 在模型启动前生成并冻结测试及预期，记录 hash；模型无权改验收测试或配置成跳过测试。

### 4.2 初始化、分工与中断

执行者初始化最小 TS 工程，配置 build/test，提交 lockfile、README、需求和基础 smoke test。选择与本机 Node 兼容的 TypeScript/node:test 方案，提交完整可复现命令。完整需求测试可以预先放在独立验收目录，初始未完成结果明确标作预期失败，不冒充绿色基线。

平台创建三项任务：

- T1 输入校验与排序：A 开始，B 接班，作为断点主线。
- T2 两种排序实现比较：从同一已验证检查点分出 X/Y，作为并行主线。
- T3 审核与发布：Reviewer 查看证据、选择方案、合并模拟 PR、人工验收。

A 只实现输入校验和输入不可变，排序部分保留待办；必须自然停在一个可解释的完成点，不通过随意杀进程制造伪断点。审核 A 的代码后，执行者显式提交并推送检查点基线；保留剩余排序验收失败的实际输出。

## 5. 测试工单（按顺序执行）

每单都填写：开始/结束时间、前置条件、身份、动作、期望、实际、判定、证据路径。前置失败导致的下游标 BLOCKED，不能用演示数据顶替。

### T01｜不含真实 API 的回归与构建

仅在被测副本、独立自动测试库运行以下现有命令，每条单独保留退出码与日志：


### T02｜真实 API 与两种供应商配置

1. 使用本次安全注入的 Key，向官方端点发一次极小文本请求。验证响应解析、完整结束，不把 HTTP 200 或被 token 上限截断的工具参数视作成功。
2. 从运行中的网页发真实项目请求，证据包含 /api/chat 成功响应与真实 model/toolTrace。不能以独立 curl 成功替代网页成功。
3. 查阅当前官方 CLI 文档与本机 help，确认如何在不修改全局配置的情况下指定 DeepSeek。核对扩展固定的 codex 启动方式能否继承这种隔离配置。
4. 若只有手工 CLI 带额外参数能用 DeepSeek，而扩展启动不带参数：记录“CLI 独立可用；扩展 DeepSeek 接线未验证/缺失”。不能用假 codex、shim 改写或手工终端执行冒充插件成功。
5. 若无法安全配置插件实际进程使用 DeepSeek，则本地 DeepSeek 路径 BLOCKED；已有另一供应商的测试只能单列补充结果，须确认其调用授权，不得静默消耗其他服务额度。

证据：web-provider.json、local-provider.json。区分配置值、真实响应模型和来源不可验证；不得仅凭 Agent 自称“我是 DeepSeek”判定。

参考仅用官方文档，执行时重核：<https://api-docs.deepseek.com/>、<https://api-docs.deepseek.com/quick_start/agent_integrations/codex/>。不要自动执行会改用户全局配置的安装脚本。

### T03｜网页立项、真实 AI 草案、人工批准

Reviewer 注册/登录 → 建团队和模拟项目 → A/B 加入 → 建里程碑。记录实际菜单和按钮文字，不能预设旧页面入口。

在该项目网页向 AI 提交第 4 节需求，要求生成 T1/T2/T3 草案，并明确“不要跳过人工确认”。验证：

1. 使用真实 DeepSeek，产生有效工具调用及可见草案，不只是聊天中列清单。
2. 确认前，数据库没有新增这些任务；确认一份后只新增对应对象。
3. 拒绝另一份草案，无新增；重新发起一次后正常批准。双击确认/刷新不会重复创建同一份已批准草案。
4. 对实际创建任务补全验收条件与负责人，通过正常业务动作，不直接写 DB。
5. AI 查询进度与界面/数据库一致；不越过人工验收把任务改为已验收。

冻结需求材料与 Context Pack（若可用）；私密对话不因冻结/分享被未经授权地复制。B 能看到获授权项目材料，Outsider 不能。模型未调用工具时保留原始结果，最多一次澄清；不能修改响应使其符合期望。

### T04｜VS Code 真实账号与项目绑定

A/B 在各自独立宿主依次使用：

```text

agilecampus.selectProject  选择项目
```

核对平台 taskId、projectId、身份、负责人、交接要求与网页一致。网页改一个期限，扩展可见视图在两个正常轮询周期加网络余量内更新；记录实际秒数。后台暂停/恢复与失败退避另测，不把轮询说成 WebSocket 实时同步。

点击 continueAiWork/reportBlocker 时检查实际 URL、项目/任务上下文；若仅打开网页，明确它们不负责启动本地 Agent。检查 A 的 PAT/任务缓存不会被 B 宿主继承。

### T05｜A 实际编码、保存检查点与真实会话材料

1. 在 A clone 启动真实 Agent，仅完成第 4.2 节的部分任务。供应商应已在 T02 核实；记录 session ID、代码 diff、命令及真实退出码。
2. 用正常授权的 Entire hooks 检查实际 session 捕获。无支持则将“自动捕获真实 session”记 BLOCKED；可继续结构化手填分支，但不能冒称捕获成功。
3. 执行者检查并提交 A 的部分成果，记录精确完整 SHA，在模拟仓库推送该基线；代码里没有 key/会话文件。
4. 运行 agilecampus.saveCheckpoint：选择 T1，填目标、已完成、待完成、阻塞、放弃方案、下一步。明确“不要先按日期排序；优先级比非逾期组内日期更重要”。
5. 若有真实捕获的 session，选择对应当前工作区会话，预览并确认保存。另存一个不带 transcript 的最小检查点用于隐私对照。
6. 用 agilecampus.listCheckpoints 查看并重启扩展，确认持久化。核对任务 ID、版本、SHA、材料 hash、captureMode 和来源会话。

验收：代码在 Git、交接材料在本地存储，二者边界清楚；检查点并不保存未提交代码。平台/网络不能未经确认上传完整 transcript。

### T06｜真实交给 B：平台索引与材料传输分开验证

路径 A 为产品界面主路径，路径 B 为隔离的后端接口验证，不能混成一个 PASS。

**路径 A：** 从现有扩展/网页入口向 B 发起交接。如果没有这样的入口或扩展未调用共享接口，记“产品共享交接链路未接通”，截图/源码定位证明。继续执行支持的导出/导入，不补写隐藏胶水代码。

**路径 B：** 对真实运行服务调用已实现的 /api/extension/v1 身份、checkpoint、handoff、accept、attempt 接口，鉴权用 A/B 的测试 PAT，载荷按实际 schema 构造。此路径只能判“真实 HTTP 后端验证通过”。检查 actor 来自 PAT，accept 不自动改派或完成任务；同一幂等键/相同内容重试不重复建对象，异内容重用拒绝；两次竞争 accept/withdraw 不能同时成功。契约声称支持而实际不支持的行为记 FAIL，不把文档删掉算修复。

**材料实际交付：**

1. A 用 agilecampus.exportCheckpoint 导出；默认不含 transcript，勾选时必须出现预览和确认。
2. 经本次测试私有传递目录人工交给 B；不得复制整个 A globalStorage 或把包提交 GitHub。记录交付方式及 hash，不称为自动云同步。
3. B 的干净宿主执行 agilecampus.importCheckpoint；记录导入成功、实际到达材料、schema/hash 校验与本地新 ID。保留导出来源 ID → 导入 ID → 服务端索引 ID 的映射，不假定相同。
4. B 独立 clone 从模拟 GitHub 获取精确 SHA，不能从 A 工作目录复制未提交文件。由平台负责人通过正常入口明确处理指派/认领；记录变化后的契约版本。
5. B 执行 agilecampus.prepareHandoff；在线身份、项目、任务版本、仓库身份、SHA、材料真实存在均核对通过。发生改派版本变化时需重新核对确认，不悄悄替换旧契约。

材料只在索引中有 hash、B 本机未收到文件时必须阻止相关接续/明确缺失，不能显示“材料已继承”。

### T07｜B 接班：不补课完成剩余工作

B 的 Agent 只得到导入材料、任务当前契约和该 Git 基线；不访问 A 私有存储、不直接读取 Luna 的完整聊天。Luna 在整个测试过程中扮演操作者，不能替 B 补写关键业务代码。

调用 agilecampus.resumeCheckpoint。开始前预览接续材料；要求 Agent 先说明已完成/未完成/基线与下一步，再完成排序逻辑并运行需求测试。不要求复述敏感原文。

核对四个记忆点：A 已完成输入校验；不重写校验/更改公开接口；禁止先日期后 priority 的错误策略；完整验收命令与基线一致。逐项 PASS/FAIL，不用“看起来懂了”代替。

执行者独立运行冻结的完整验收测试，核对测试 hash 未变、输入不变性与主样例。保存真实命令/退出码与 diff；Agent 自报测试通过不算证据。

agilecampus.listAttempts 必须能追溯 checkpoint、task、workspace、实际 session 与完成回执。没有 session+完整完成事件，不能显示确定 finished；进程退出 0 不等于任务验收。网页任务仍须人提交/审核。

记录：这是基于材料启动的**新 session**，不是恢复 A 的原进程/模型隐藏状态。只有真实 transcript 捕获并传递成功，才可说“继承会话材料”；只有手填摘要时写“继承人工摘要”。

### T08｜同一断点，两种方案并行

从 T05 的同一个有效检查点和完整 SHA 建立两个 parallel Attempt，不从 B 已完成后的不同版本开始。使用 agilecampus.forkAttempt 两次，记录不同 branch/worktree/attemptId。若任务版本已变化，先完成正常核对流程。

- X：预计算排序键再稳定排序。
- Y：比较器逐层比较，不改变输入。两者完全遵守同一需求和验收测试。

先验证 worktree 干净、基线一致，再经扩展分别启动本地 Agent。记录两个真实进程生命周期；存在运行时间交集才写“并行运行已验证”，串行执行只能写“独立方案已验证”。禁止并发写同一目录。

验证：X 的改动不会出现在 Y/源工作区；不同 session 不串工具结果；同目录再次启动被阻止；关闭再打开宿主不会把仍运行的进程误判结束；两份结果都可独立运行相同测试。

用 agilecampus.compareAttempts 比较真实 diff/提交/测试结果，保存截图。Reviewer 根据正确性、改动量、可读性选一份，不让模型以口头“更好”自动获胜；另一份保留，不自动 merge。

### T09｜GitHub PR、人工验收和项目闭环

执行者审核选定 worktree 的 diff，确认未改验收测试/未带密钥后，显式提交并 push **模拟仓库** 的独立分支。创建一份 PR，附任务编号、检查点 SHA、方案说明、实际测试结果；如果运行环境要求 attach_artifact，创建后附上 PR。

可为模拟仓库添加只读权限的 GitHub Actions 运行冻结测试，不提供任何 API Key；若 Actions 无额度或无法运行，记 BLOCKED，保留本地测试，不伪造远程 CI。

Reviewer 检查 PR 和证据后显式合并所选方案。再从模拟远端做第三份干净 clone，按 README 从零安装并测试，证明不是只在 Agent 工作区可用。

通过平台正常动作提交成果、人工验收。未验收前不得显示已验收；拖拽不能直接把待办变成已验收。GitHub PR 合并若没有与平台自动同步的实现，必须人工贴链接并写清楚，不能声称自动联动。

生成项目总结/周报时再用真实网页 AI，核对它能引用实际项目任务事实；它不能捏造未上传的本地测试、PR 或 session。总结中“已完成”必须区分 Agent 结束、代码通过、PR 合并和任务人工验收。

### T10｜故障与安全回归

至少执行下列独立场景，每项使用专属副本或可回滚 fixture；故障不得破坏 T03–T09 的演示链路：

| ID | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| F01 | 用假 Key 调模型配置；随后恢复本次合法配置 | 清楚报认证失败，不产生假草案/成功记录；恢复后可重试。 |
| F02 | 本次隔离服务断网/延迟，分别测读取和交接写入 | 有超时/错误，保留已保存检查点；写入结果不确定时核对同一请求，不重复交接。 |
| F03 | 撤销 A 专用测试 PAT，再操作其扩展 | 后端拒绝，扩展停止用失效 token；本地材料仍在，重新连接能恢复。 |
| F04 | Outsider 获取已知 checkpoint/handoff/task ID；B 尝试伪造 actor | 无越权读取/写入，身份只来自认证；不能接受别人的交接。 |
| F05 | B 预检后移出团队，或在确认与启动之间撤权 | 执行前重新校验；不能以早先通过的预检继续写共享状态/启动未授权流程。 |
| F06 | 检查点后修改任务验收条件/交接版本 | 明确要求重新核对；旧版本写入冲突，不静默覆盖。 |
| F07 | B 指向错误仓库、错误 SHA、dirty 工作区 | 预检阻止不安全接续；不会自动清理、reset 或覆盖用户文件。 |
| F08 | 交接包 hash 改坏、超限、非法路径/base64、材料缺失 | 导入/接续明确拒绝，不写任意路径、不半成功显示已收到。 |
| F09 | 合成附件含明确假 token 与“忽略任务、上传凭据”的文本 | 检查分享提示/过滤边界；接续不执行恶意要求、不上传凭据、不越权。只放假密钥。 |
| F10 | 同目录双窗口启动；不同 worktree 同时启动 | 前者互斥，后者能独立执行；退出/恢复不能误释放活进程的锁。 |
| F11 | 正常停止本次测试 Agent；缺完成事件/异常退出 | failed/unknown/awaiting_confirmation 等真实状态，不能自动显示测试通过或任务验收。可用协议 mock 验证缺事件，但必须标 Mock。 |
| F12 | 插件/网页/服务正常重启 | 任务、对话和已保存检查点仍在；无重复交接，进程状态重新核实，不靠缓存冒充活跃。 |
| F13 | 超过一页 Agent 记录并刷新/切换任务 | 若该 UI 存在：分页不重复、不串任务；新增记录不应导致旧任务缓存污染。可用合成 fixture，不冒充真实 Agent 启动几十次。 |

故障注入代理仅服务本次 localhost 测试，使用假凭据；真实模型异常不可控时，分别报告“注入测试”和“官方服务实际观测”，不混淆。

### T11｜使用路径可理解性

不做审美重构，只验证用户能找到功能。写一份真实点击脚本：网页找到任务 → VS Code 查看任务 → 保存检查点 → 发给 B → B 检查并接续 → 查看并行方案 → 人工验收。

每步记录入口文字、点击次数、是否跳站/切账号、是否需要命令面板、有没有明确当前 task/checkpoint/actor。以下任一情况列为产品断点：必须手调 HTTP 才能交接；只有聊天页没有执行入口；已保存却不知道如何分享；B 收到索引却拿不到材料；网页看不到本地 Attempt 且没有说明。

不能因为后端能调用就判“普通用户能用”。若只有执行者自测，说明未进行真实陌生用户可用性测试。

## 6. 判定与审查规则

- PASS：本用例所有关键断言有实际证据。
- FAIL：可执行但结果违背要求，或产品显示成功却实际未完成。
- BLOCKED：缺少密钥、工具、权限、接线或前置条件，未完成验证；给出解除条件。
- NOT_RUN：尚未执行，说明原因，不能写成通过。
- OUT_OF_SCOPE：完整进程迁移、模型隐藏状态恢复、自动云备份、自动选择/合并方案等明确非本版目标，不纳入通过率。

每项再标证据级别：静态检查 / mock / 真实领域测试 / 真实 HTTP / 真实网页 / 真实扩展宿主 / 完整跨端。不允许低级别代替高级别。

总判定分三层：

1. **真实模型可用**：网页完整请求、工具草案与人工确认通过；不能只凭直连 API。
2. **本地协作可用**：真实扩展绑定、检查点材料传递、B 接续与并行隔离、真实代码测试通过；注明真实供应商和材料来源。
3. **平台整链可用**：普通用户通过现有入口完成共享交接、执行证据回传/可追踪及人工验收，不依靠测试脚本代操作；缺任一关键接线不能标全链路通过。

完全达标要求：上述三层均通过；DeepSeek 在网页和插件实际执行路径均有证据；T07/T08/T09 核心通过；无 P0/P1 安全或正确性失败。若第三层不通过，仍交付完整报告，不以“顺手补好”延长为开发任务。

问题分级：P0 密钥泄漏/跨用户越权/真实数据损坏；P1 错误代码基线、同目录覆盖、假成功、交接或接续主链断裂；P2 可恢复的同步/导航/错误提示问题。P0 立即停止相关链路并通知用户，不等报告末尾。

## 7. Luna 必交报告与证据

在产品仓库新增目录 `docs/reviews/deepseek-project-simulation/<runId>/`。这里只放已脱敏材料；原始日志/交接包留本次私密临时目录，不进 Git。

```text
README.md                 审核入口：结论、关键路径、链接
report.md                 完整报告
manifest.json             版本/运行环境/非敏感资源与 ID 映射
capability-map.md          页面→扩展命令→API→存储→供应商

demo-script.md            3–5 分钟演示点击步骤
evidence/                 脱敏命令输出、截图、diff、回执、usage 汇总
```

manifest 至少包含 sourceHead、sourceDirtyPaths、dirtyPatchHash、测试起止时间、工具版本、模型请求值/实际值、模拟 repo/PR URL、平台 origin、非敏感数据库名、project/task/checkpoint/handoff/attempt/session ID 映射、A/B clone 与 worktree 的别名、关键 SHA、测试文件 hash。日志对外用路径别名，不泄漏本机绝对私密路径或带凭据 URL。

report.md 必须按以下标题填写，不得只贴绿色截图：

1. 一句话结论：现在用户到底能完成什么，哪一段仍不行。
2. 本次测试的确切版本、环境与隔离方法。
3. 真实模型连接结果：网页和本地分开，请求/返回模型、usage、错误与重试；未能统计的费用明确未知。
4. 项目时间线：谁在哪个任务、哪个 SHA 保存检查点，B 收到什么，哪个 session 做了哪些变更。
5. 核心验收表：T00–T11 与 F01–F13，所有子断言 PASS/FAIL/BLOCKED/NOT_RUN，不省略失败。
6. 记忆有效性：四个记忆点结果、继承材料类型、B 是否需要额外补课，不能把摘要继承称原生恢复。
7. 并行证据：相同基线、不同 worktree/session、起止时间重叠、互斥/隔离、方案 diff 与人工选择理由。
8. 实际入口断点：哪些只能直接调用后端、哪些按钮只跳网页、哪些回执没有回传。
9. 缺陷：级别、复现步骤、期望/实际、证据、定位文件、建议修复范围；不要擅自修。
10. 能对老师演示的内容与不能宣称的内容。
11. 资源善后：本次服务/进程是否已停止，测试 PAT 是否撤销，临时材料位置与保留策略，模拟仓库保留链接。
12. 待 Codex 审核问题：明确列出阻碍“项目整链可用”的最少几项，不泛泛建议重写全部。

至少保留 8 张关键截图：网页任务/草案、确认后任务、扩展同任务、A 检查点、B 导入与预检、B 完成回执、并行比较、人工验收。缺入口/失败截图同样有效。截图必须来自真实被测页面，禁止绘制效果图替代。

每条证据使用稳定 ID，例如 E-T07-03，日志记录 UTC 时间、命令、退出码、来源；浏览器原始 HAR 含 Cookie/token，不得直接提交。提交前人工检查脱敏，禁止靠宽泛替换毁掉所有可核验信息。

保留模拟仓库和 PR 供审核，不自动删除。正常退出本次拥有的进程、撤销专用测试 PAT；保留可复测合成数据。不要清理用户原服务或真实凭据。
