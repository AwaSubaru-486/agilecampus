## 2. 已核对的体验问题

以下来自当前源码检查，未作为真实用户测试结论：

1. `vscode-extension/package.json` 的 `view/title` 同时挂保存、摘要发布、交接、导入导出、检查、启动和并行等大量操作。用户要自己拼流程。
2. `webview/src/App.tsx` 首屏主要是项目元信息、任务列表和交接要求；没有关联会话、本地记录、已分享版本、接班进度的可见入口。
3. 当前 Webview 每收到项目 snapshot 会清空详情缓存并重新请求；后续若直接塞入记忆编辑，会带来闪烁和丢失编辑上下文的风险。
4. `WebviewMessage` 只有连接、刷新、打开任务/网页等消息；没有会话命令、操作回执和会话状态。
5. 现有 `unbind` 是结束绑定，同一原生会话不能重新绑定；不能把它直接包装成「暂停/继续」开关。
6. 网页二级导航实际由 `src/app/(app)/_shell/top-workbar.tsx` 渲染。只改静态导航配置不足以让入口出现。

## 3. 用户主线与术语

正常路径固定为：

```text
A：选任务 → 关联会话 → 自动记录 → 发布断点 → 交接给 B
B：打开收到的断点 → 查看记忆及出处 → 核对代码 → 启动 Agent → 发布下一断点
```

「发布」让项目成员能够读取这一版材料；「交接」指定接收者并沿用现有接受规则。发布成功不代表已改派，收到交接不代表 Agent 已运行，Agent 结束不代表任务已验收。

| 用户界面词语 | 具体含义 | 不允许混用 |
| --- | --- | --- |
| 会话 | 一次已关联任务的来源对话 | 不是任务本身，不是单条消息 |
| 记录 | 本机保存的对话事件/来源材料 | 不写「已同步」 |
| 记忆 | 带出处的任务目标、约束、结论和下一步 | 不把模型推断写成已验证事实 |
| 断点 | 冻结的记忆、材料和代码基线版本 | 不等同于代码或整个工作区备份 |
| 接班 | 收到材料、核对环境、启动新 Agent | 不承诺还原隐藏推理状态 |
| 尝试 | 某个成员/Agent 在独立工作区的一次执行 | 不等同于另一个任务 |

旧 checkpoint/attempt 等代码命名保留。日常界面统一中文术语，来源工具保留 Codex/Claude 名称；不附重复英文标题。

## 4. 页面与操作位置

### 4.1 VS Code：一个项目侧栏，一份当前任务上下文

保留现有 Activity Bar 容器和 `agilecampus.projectView`。标题栏仅保留「刷新」和原生更多菜单；连接未完成时显示「连接项目」。选择项目、断开、兼容命令放更多菜单/命令面板。不要删除旧命令 ID。

侧栏内容从上到下：

```text
项目名                                   [更多]
任务选择器：#42 修复登录回调
分支：fix/login

会话                         [关联会话 / 更换来源]
来源：Codex
记录：接收中    最近保存 14:32:18    28 条
分享：未发布
[查看记录]              [发布断点]（M04 后出现）

收到的交接（M06 后接入真实列表）
张同学   #42   断点 v3              [查看]
```

这是顺序示意，不生成等宽整页 UI。用有标签的行和实线分隔，项目/仓库详情在「项目详情」展开区；首屏只保留当前任务、代码分支、会话和操作。已有项目任务列表作为任务选择来源，保留任务详情入口。

「查看记录」打开一个可复用的编辑区面板，避免在 320px 侧栏塞入完整长对话。选中任务不等于修改会话绑定。若用户看另一任务，原绑定继续按原任务记录，界面明确显示当前查看任务，不能把原会话悄悄迁过去。

首批只显示已接通的本地记录功能。后续按钮随对应阶段完成接入；有能力但暂缺配置时显示操作及具体缺项，尚未实现的能力不放一个可点击假按钮。

### 4.2 网页：沿用两级侧栏，新增一个「会话」入口

在项目一级分组下加入「会话」二级项，与任务等现有项并列。折叠侧栏后仍能展开/定位选中项，当前项目切换与会话路由同步。不要再新增「记忆中心」「AI 中枢」「接力大厅」。

复用 M05 的列表/详情路由，列表列为任务、会话、成员、Agent、版本、发布时间、交接状态。列表按任务/成员筛选，最多一条工具栏；不加入 KPI 卡片。点击行进入详情，浏览器返回恢复筛选、分页与行位置。

详情默认显示记忆；「对话」「版本」是当前对象的视图切换，不是新的全站导航层。直接使用带标签的事实段落/列表，不嵌套卡片。任务、版本、发布者、来源放一行元信息；校验细节按需展开。

来源会话可能含未分享部分，网页只显示被授权并实际发布的固定版本，不访问 A 本地文件。任务详情到同一会话详情使用同一个 URL 构造器。

## 5. 人性化行为规则

### 5.1 关联时少填、不错绑

- 项目与工作区优先使用当前已验证绑定；任务预选当前选中任务，允许更改，不能猜任务。
- 「关联会话」显示当前工作区可核对归属的来源列表：工具、开始时间、最近活动、可读标题。会话原生 ID 仅诊断展开可见。
- 普通已配置路径最多两个选择步骤：任务（已有选择时跳过）、来源。选中来源后在同一视图显示关联结果。
- 首次启用采集另有一次明确配置说明与用户启用动作；调用工具官方信任流程，不能静默安装全局 Hook。没有来源时显示「未发现当前工作区的会话」和「重新检查」，不返回一页空白。
- 不支持的来源显示具体原因；记录 Hook 可见事件但无法取得完整对话时，写「部分记录」，不写「完整记忆已保存」。
- 「解除关联」放更多菜单，说明停止后保留历史、原生会话不能重新绑定。首批不提供「暂停/恢复」；后续若增加，须独立实现可恢复采集策略，不能调用现有 unbind 冒充暂停。

### 5.2 随时知道记录是否有效

采集、发布和执行是三个独立状态域，不设计一个覆盖一切的 status，也不更改任务状态机。

| 记录状态 | 显示 | 用户下一步 |
| --- | --- | --- |
| 未关联 | 未关联会话 | 关联会话 |
| 启动/恢复中 | 正在检查记录来源 | 可继续阅读已有记录 |
| 接收器正常且无新增内容 | 等待新记录，最近保存时间/条数 | 查看记录；不因对话安静而报故障 |
| 刚收到且落盘成功 | 已保存 N 条，最近保存时间 | 查看最新记录 |
| 来源/接收器故障 | 记录已中断，具体原因 | 重新检查；本地历史仍可读 |
| 存在已确认缺口 | 部分记录，缺失范围或范围未知 | 查看缺口、尝试恢复 |
| 已解除关联 | 已停止记录 | 查看历史、关联新的来源会话 |

成功状态必须在本地写入确认后更新。来源健康检查时间和最后事件时间分别保存；未到新事件不等于掉线。持久化绑定不能在重启时直接恢复为「接收中」，必须重新核对监听器。

### 5.3 记录阅读不打断工作

- 编辑区分「记录」「记忆」「版本」；H02 只有已可用的「记录」。工具调用和长日志折叠成一行，显示命令及已知退出码，按需展开；用户/助手正文可连续阅读。
- 新记录到达时，用户在底部才自动跟随；正在向上阅读则显示「N 条新记录」，点击后跳到最新，不抢滚动和焦点。
- 分页或窗口化渲染，首批加载 50 条；向前加载保留当前记录锚点。来源缺口用文字行明确标注，不能把未知区间伪装成完整聊天。
- 打开记忆出处要定位到具体记录；「返回记忆」恢复原条目位置。没有证据时直说「未找到可核对记录」。
- 刷新项目不会清空当前阅读位置或编辑草稿；请求返回晚于项目/任务切换时丢弃旧响应。

### 5.4 发布有结果、有边界、可恢复

- 首次配置分享范围后，正常路径点击一次「发布断点」。自动执行冻结、提炼、脱敏、上传、回读核验和平台登记。
- 「预览/编辑」是旁路，可看将要分享的范围、记忆和排除内容。新发现敏感信息、分享范围变化或材料不完整时，进入具体问题的确认/修正界面。
- 在原位置显示当前阶段：整理记忆、上传材料、核验材料、登记版本；不伪造百分比，也不锁住整个页面。
- 点击后立即显示进行中并阻止重复提交；只有服务端确认后才能显示「已发布 vN」。材料已上传但登记失败显示「材料已上传，登记待重试」，提供「继续发布」。
- 关闭面板继续后台操作；「停止后续步骤」才请求取消。已发送的模型/上传请求可能仍完成，应查询操作状态；不可显示已经撤回远端材料或承诺取消不计费。
- 发布中新增的记录继续保存，当前发布保持固定范围，完成后显示「另有 N 条新记录未发布」。同输入重试复用已有结果，不重新提炼收费。
- 编辑默认保存本地草稿，保存失败保留输入并提示；已发布版本不被覆盖。编辑未发布内容要明确标「本地草稿」。
- 成功后提供「查看发布版本」「交接给成员」。交接表默认带入当前任务和版本，仅选择接收者/填写可选附言；不重新手填整个交接表。

### 5.5 接班先给结论，阻塞时给具体处理动作

固定预检顺序：材料权限及完整性 → 代码仓库与基线 → 工作区修改 → Agent 可用性。界面显示当前阶段，失败只展开相关项。通过项可以折叠，不能要求用户对每项逐个打勾。

干净且符合基线的工作区，完成必要接受动作后，一个明确的「启动 Agent」操作完成正常启动；已有授权不重复询问。脏工作区时默认提供「在独立工作区继续」，并清楚列出将创建的路径/分支；复用 worktree 服务，不自动清理现有文件。

启动区始终展示来源成员、任务、断点版本、代码基线。材料下载成功显示「材料已就绪」，真实启动器回执成功才显示「Agent 已启动」。网页无法确认插件安装或启动结果时显示「等待 VS Code 响应」，并提供安装/复制断点标识的后备入口。

Agent 首次接班说明固定输出目标、已确认结论、未解决事项、准备执行的第一步；普通路径无需再弹确认。与实际代码/任务冲突时暂停执行并标出具体矛盾，交给用户决定。

并行尝试只放在断点详情的「更多 → 从此断点并行尝试」，复用已存在的 `fork-attempt`。展示派生来源、成员、工作区、运行状态、测试结果；不默认打开分叉树，不自动排名、合并或替负责人选方案。

### 5.6 通知、输入与文案

- 成功优先在操作原位反馈；同一次持续故障只提示一次，详情中保留恢复入口。普通新事件不发 Toast、不用红点催促。
- <100ms 目标是点击有视觉响应；超过 1 秒显示加载反馈，超过 10 秒显示阶段/耗时和可离开的入口。未知总耗时不编造倒计时，不为了动画人为延迟。
- 业务写入不乐观显示「已发布/已启动/已验收」。阅读切换、展开折叠可即时响应。
- 键盘可完成选择、查看、展开出处与关闭面板，关闭后焦点回触发控件；不抢编辑器常用快捷键。
- 每个控件可通过键盘获得含义，图标具名称。状态用文字表达，颜色是辅助；屏幕阅读器仅播报重要状态变化，不逐条朗读采集计数。
- 禁用操作显示具体条件，如「来源不完整，暂不能发布」和对应修复入口；去掉无信息量的「操作失败」「未知错误」「立即开启智能协作」。
- 普通标题不附宣传式解释段落。必要的错误原因、分享范围、不可逆行为说明保留，避免为了少字让用户误操作。

## 6. 视觉约束

方向：Developer Tool / CLI Companion。使用者是开发成员，主动作是记录/发布/接班；风格服务于快速找信息与核对证据。

| 项目 | 约束 |
| --- | --- |
| 组件 | 网页沿用已有 shadcn 基础组件；扩展沿用 VS Code 原生选择器、菜单和主题变量；不引入另一个管理后台模板 |
| 配色 | 网页沿用 background/foreground/muted/border；扩展使用 `--vscode-sideBar-background`、`--vscode-foreground`、`--vscode-descriptionForeground`、`--vscode-panel-border`、`--vscode-focusBorder` 等语义变量；尊重用户 IDE 主题 |
| 字体 | 扩展使用 `--vscode-font-family`、`--vscode-font-size`；网页沿用现有无衬线字体，正文 14px、标题 18px；命令/路径/代码使用已有等宽字体 |
| 密度 | 间距 4/8/12/16/24px，网页列表行约 40px；扩展控件至少 32px 可点击区域，触摸端至少 44px；长标题换行，不截掉唯一可区分的任务名 |
| 容器 | 列表、实线分隔、定义列表；正文不加卡片外壳；控件沿用 3–4px 小圆角，普通区域无阴影，浮层沿用原组件阴影 |
| 图标 | 优先已有图标；扩展使用现有可用图标资源/原生菜单，不用 emoji 或魔法棒表示 AI |
| 动效 | 仅展开、焦点、加载反馈，约 100–150ms；尊重 reduced-motion；原生滚动，无装饰位移 |

禁止彩色标题竖线、虚线装饰框、重复中英标题、大圆角卡片矩阵、渐变、装饰性状态圆点、拟人宣传句。允许用户自选 VS Code 主题的原生颜色，不硬编码覆盖整个 IDE 风格。

### H01：接通关联入口与侧栏状态

依赖：H00、M02 的 provider 能力核对。修改：`package.json`、`src/extension.ts`、`src/types.ts`、`src/views/{project-view-provider,webview-message}.ts`、`webview/src/{App.tsx,styles.css}`；拟新增 `src/commands/bind-session.ts`。
