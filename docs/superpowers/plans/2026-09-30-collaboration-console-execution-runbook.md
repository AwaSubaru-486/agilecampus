# 人-Agent 协同执行台：Luna 逐单施工手册

状态：计划已写入，代码未开始执行。适用于 Luna、Sol 或其他下游执行模型。

## 先读这 10 句话

1. 你要改的是 `/projects/[projectId]` 项目页面，不是重写整个网站。
2. 用户要看见“人分配工作 → Agent 做事 → 人处理阻塞 → 人验收结果”。
3. 不是加一个聊天框，也不是给旧卡片换颜色。
4. 保留现有数据库、权限、任务动作和运行上报规则。
5. 左侧选任务，中间看任务要求和交付物，右侧看 Agent 的真实执行记录。
6. 导航只有两层：点击“项目”展开“项目列表 / 执行 / Agent / 记录”。后三项必须有当前项目；没选项目就只显示项目列表，不链接到随便一个项目。
7. 人、Agent、任务状态、运行状态是四件不同的事，不能混在一起。
8. 会话分支只复制可见的对话上下文，不等于恢复 Agent 的进程、代码分支或运行环境。
9. 不存在的能力不能做成可点击的假按钮；记录缺口，但继续做不依赖它的工单。
10. 从工单 00 开始，一次完成一个工单。通过检查再做下一个，不一次重写全部文件。

本文是执行步骤。[产品与架构计划](2026-09-30-human-agent-collaboration-console-rebuild.md)解释原因。发生冲突时，本文的能力边界、工单顺序和验收规则优先。已有 AGENTS.md 的安全和协作边界不变。

## 一、术语：不能自己换意思

| 名词 | 在本项目里是什么意思 | 不是什么 |
| --- | --- | --- |
| 任务 Task | 有负责人、要求、截止日期和验收状态的工作 | 一次聊天 |
| 运行 AgentRun | Agent 对任务的一次执行记录 | Task 状态或聊天会话 |
| 交接契约 Handoff | 交接目标、完成标准、证据要求 | 对话的随意摘要 |
| 上下文包 ContextPack | 有来源和冻结状态的资料集合 | 任意拼接的全部项目数据 |
| 会话分支 | 从指定消息创建子会话 | Git branch、worktree、运行进程恢复 |
| 证据 Evidence | 与任务绑定、可追溯的交付记录 | 模型说“我完成了” |
| 人工验收 | 有权限的人根据交付物通过或退回 | Agent 自己决定任务完成 |

代码协同通过真实的仓库链接、提交/PR/测试证据体现。当前没有可验证的 Git 分支、diff 或运行工作区关联时，显示已有证据；禁止画假的代码终端、分支树、测试绿勾。

## 二、已查明的能力边界

以下是编写计划时对当前代码的检查结果。执行时仍要核对最新 HEAD。

| 能力 | 已知入口/事实 | 本轮怎么处理 |
| --- | --- | --- |
| 查看运行 | `src/lib/agent-run.ts`：`listTaskRuns` | 服务端先鉴权再调用，不直接信任传入 taskId |
| Agent 上报 | `POST /api/agent/runs`，使用 Bearer 身份 | 这是 Agent 的上报入口，不是浏览器启动 Agent 的接口 |
| 运行排队 | `enqueueRun` 目前只找到函数定义，没有调用方 | 不新增一个按钮直连数据库，不把函数存在说成启动功能已完成 |
| 会话分支 | `POST /api/conversations/[conversationId]/fork` | 复用真实接口，按钮准确叫“从此消息创建会话分支” |
| 分支请求体 | `throughMessageId` 必填；`title`、`visibility` 可选 | 不传虚构的 runId、checkpointId 或 branchReason 字段 |
| 分支响应 | HTTP 201，`{ conversation }` | 读取实际返回的会话 ID；失败不切换选择、不显示成功 |
| 任务操作 | `actions.ts`：claim/decline/submit/review 等 action | 保持原签名、鉴权、表单字段、返回错误 |
| Agent 完成 | 写入 run 证据后调用 `submitTask` | 证据不满足要求会提交失败；不能强行显示待验收 |
| 真实进程续跑/停止/重跑 | 本次检查尚未验证用户可调用的接口 | 按缺口处理，不做可用按钮，不用聊天接口替代 |
| 完整工具日志 / 每步 checkpoint | 不保证每个 Run 都有 | 有什么显示什么，无数据写“暂无记录”，不用 AI 编造 |

正式运行的完整闭环属于验收 B。没有后端支撑时，本轮最多完成验收 A；最终不能说“断点执行交接全部完成”。

## 四、固定路由规则（照表实现）

允许修改 `src/lib/project-space.ts` 和 `tests/project-space.test.ts`，因为它们属于展示路由规则，不属于任务状态机。

| 输入 | 规范化结果 | 导航选中 |
| --- | --- | --- |
| 无 space、非法 space | `space=work` | 执行 |
| `space=work` | 保持 | 执行 |
| `space=studio` | 保持，使用共享执行台的 Agent 视图 | Agent |
| `space=record` | 保持 | 记录 |
| `space=live` | `space=work`，保留现有参数 | 执行 |
| 任意 space + 非空 conversation | `space=studio`，保留会话参数，随后鉴权 | Agent |
| 任意 space + 非空 approval | `space=studio`，保留审批参数，随后鉴权 | Agent |

规范化必须是幂等的：规范化两遍等于一遍。不得在 work/studio 之间循环重定向。

数组参数沿用取第一项规则。不删除 task/conversation/approval 和现有合法筛选。未知 ID 不自动当作有权限；数据层验证后显示“记录不存在或无权访问”，不泄露名称或存在性。

任务选择：

- 用户点击任务时 `router.push` 当前页面的新 query，保留过滤参数，`scroll: false`。
- 切到另一任务时清掉旧 `run/conversation/approval`，避免把 A 任务内容显示在 B 任务下。
- 无 task 时选择第一个待处理任务，不抢焦点；默认选择用 replace 写入 URL，不制造额外返回历史。
- task 明确传入但不可访问时，显示无权/不存在，不悄悄替换成另一任务。
- 搜索与过滤使用 replace；用户明确切换任务使用 push。
- 跳转允许 Next.js 服务端读取新数据；“不整页跳转”指不 reload 浏览器，不要求全部数据驻留客户端。

## 五、固定视觉规格（不再自由发挥）

### 标题文案硬规则（用户追加，2026-09-30）

- 页面、分区、抽屉的标题下不放介绍性副标题：禁止解释“这个模块能干什么”“系统如何生成数据”“AI 如何帮助协作”。直接删除，不换一种措辞重写。
- 标题后直接进入工具栏、数据、表单或列表。真实项目名、记录数量、状态、截止日期可保留；用户填写的任务描述和决策问题不是装饰文案，不删除。
- 错误原因、权限条件、字段必填要求、令牌权限说明、图表图例等影响操作的信息保留在对应控件或内容附近。不得为了删副标题同时删除这些信息。
- 表单标题和按钮用直接的动作名称：认领任务、提交成果、验收、拒绝认领。不要用“这份活你接得住吗”“交出去”等拟人化表达。
- 全站适用，验收时覆盖今日、项目任务、Agent 会话、资料库、成果记录、风险、复盘、活动和任务抽屉；`npm run check:ui-copy` 检查已删除文案不得回流。

这是重构，不是品牌设计比赛。复用 `src/components/ui/` 已有 Button、Table、Drawer、Timeline 等源码，先查看它们实际的 props。不要假设安装了 Radix 或 shadcn CLI。

- 方向：工程控制台；暗色中性主题，遵循用户提供的黑灰参考；不使用暖灰、米色、渐变。
- 颜色：沿用现有语义 token；新工作面目标背景 `#0a0a0a`，面板 `#171717`，边界 `#404040`，正文 `#fafafa`，次要文字 `#a3a3a3`。控件焦点使用现有高对比 focus token，不只靠边框或颜色区分状态。
- 若全局 token 与此冲突，只对执行台做作用域映射，不无意改变其他页面。
- 字体：现有 system sans；正文 14px/20px，元数据 12px/18px，任务标题 16px/24px；ID、路径和日志用现有 mono。禁止大字标语。
- 间距：4/8/12/16/24px；任务行至少 44px，顶部控件高 36px，移动端点击区域至少 44px。
- 圆角：列表和分栏 0px；按钮/输入沿用 6px；抽屉沿用 8px。分栏不加阴影，弹层才用既有阴影。
- 图标：用现有图标实现；不新增 emoji、装饰点、彩色竖线或虚线大框。
- 动效：仅面板开合，最长 150ms；reduced-motion 下关闭非必要动画。
- 主按钮每个当前操作区最多一个；默认中性高对比，不铺满蓝底。
- 顶部标题只显示项目名；信息真实存在才展示，不放“项目状态、任务进度、Agent 入口”等解释句。

按**可用内容宽度**而非整屏宽度布局：

- ≥1120px：任务 280px / 契约 minmax(400px, 1fr) / Agent 320px，分隔线 1px；
- 760–1119px：任务 280px + 契约剩余宽度，Agent 通过“执行记录”打开 Drawer；
- <760px：任务列表或任务详情二选一；详情顶部有“返回任务”，Agent 用独立 Drawer；不是三个长面板纵向堆在一起。

侧边栏继续可折叠。大屏与小屏不能同时挂载两份可交互 TaskDrawer。Agent 视图复用同一任务详情和执行轨，只把左侧列表换成运行列表，不复制业务状态逻辑。

### 工单 01：先写纯规则和测试，再做页面

规则：

1. 一个任务只进一个优先组，按主计划第 4.2 节从前往后匹配；“等待我确认”必须同时满足审核/审批权限，不是所有 pending 都归我。

3. 活动 Run 明确包含 queued/dispatched/running；不能只复用漏掉 queued 的查询就认为没有运行。
4. 多条运行先按活动/非活动分区，再按 createdAt 降序；时间相同按 id 字典序固定排序。不把多个运行合并成一条。
5. failed Run 不能把 Task 改成 failed；completed Run + doing Task 必须保留 doing。
6. 未知状态显示“未知状态”，不默认当成功；无运行是“暂无执行记录”。
7. 主动作由真实能力 + 当前用户权限 + Task 状态决定；无恢复能力就没有“继续运行”。

至少写 10 个测试：待审核有/无权限、queued、不带 Run、运行失败、完成但提交失败、blocker 已解决、两个不同任务、同时间稳定排序、未知状态。纯规则函数不能调用 mutation。

检查宽度 1440、1024、615、390px；检查侧栏展开/折叠、长标题、长日志、空结果、401/403、网络失败、忙碌状态。页面不能横向溢出；日志允许自身横向滚动。

键盘 Tab 能到所有按钮；链接有名称；Drawer Escape 可关闭并还原焦点；状态不只靠颜色；不能给普通列表套上未实现方向键操作的 ARIA grid。

视觉评审使用 anti-ai-slop-ui 规则，但不以“独特”为由推翻用户要求的中性 shadcn 风格。未实际看页面前不填写视觉评分；检查后报告具体残留问题，不把“AI 率”当真实检测指标。

## 七、验收 A：本轮必须完成的真实 UI 重构

逐条标注通过 / 失败 / 未验证，附入口和操作结果：

1. 打开项目：二级导航出现执行/Agent/记录，默认执行，无营销文案。
2. 左侧选任务：中间显示该任务要求，右侧显示它的真实 Run，不混入其他任务。
3. 看一个 completed Run 但 Task 仍为 doing 的测试场景：两种状态分别如实显示。
4. 看一个真正的 blocker：有原因与已有操作；解决后读取真实状态。
5. 在已授权会话的一条消息上分支：子会话有父来源，不出现“代码执行已恢复”的提示。
6. 提交证据后按现有规则验收：通过才 done；拒绝/校验失败不报成功。
7. URL 刷新、复制、返回一致，旧 live/studio 链接没有死路。
8. 无权限账号无法读到私密会话/其他项目 task/run/审批。
9. 窄屏可完成相同动作；导航可折叠；不存在覆盖全屏且无法关闭的层。
10. 真无运行数据时显示暂无执行记录，不显示演示假 Run。

## 八、验收 B：真正代码 Agent 交接（不得冒充已完成）

仅在真实执行器与用户授权入口已接入后才验收。未接入就全部明确标为未实现/未验证：

1. 人发起执行，真实执行器领取任务，而非网页伪造 running；
2. 运行绑定真实仓库、版本和上下文快照；
3. Agent A 阻塞后保存可交接材料，包括尝试过的方法、未完成工作、代码版本、验证结果；不要求暴露模型内部思维链；
4. 人明确指定 Agent B；B 取得被授权的同一资料与代码状态，旧 A 不再并发写同一任务；
5. B 实际继续工作并产生新代码/测试证据；
6. 审核者可以从任务追到两次 Run、交接人、版本与证据，最后人工验收。

缺任何一项，都只能说“协同展示/会话继承已完成，代码执行交接待接入”，不能说“Lody 式断点协同完整实现”。这不是降低主旨，而是把主旨拆成可证明的能力。
