# AI 助手后端完善

保留现有项目对话前端和响应字段，只修改后端、测试及文档。

## 项目协助能力

- 新增执行阶段进度查询，按当前阶段的叶子任务计算验收比例，并分别报告未验收任务、缺少交付分支及最新集成审核结果。执行阶段与里程碑明确区分。
- 新增项目成员工作量查询：真实角色、已分配与未完成任务数、未接住、逾期及求助数量。老师标为非执行角色；数量不作为工时或能力评分。
- 新增未解决求助查询，以及任务详情查询，包含说明、完成条件、前置任务、已有与缺失证据和交付资料。
- 新增可见草案状态查询，当前会话仅查询自己的来源建议；任务清单支持阶段与关键词过滤，并返回负责人及阶段 ID。
- 项目快照增加当前提问者身份和当前阶段验收比例；任务关联会话自动带入任务资料，不要求用户重复描述。所有读取仍经过现有成员及项目权限检查。

## 续聊和可靠性

- 数据库只读取近期人机历史供 AI 使用，继承最近 40 条并以 24000 字符控制总预算，单条长消息保留首尾且明确标注裁剪；工具消息不作为普通聊天历史回灌。前端仍可以获取全部会话历史。
- 消息输入限制为 20000 字符，模型调用传递请求取消信号，并设置 90 秒超时及输出长度限制，继续保持零自动重试。
- 超时返回 504，取消返回 408，沿用前端已有 error 字段。模型取消或没有有效回复时不写入半轮消息；只有草案而无正文时提供明确的待确认说明。
- 工具轨迹按 toolCallId 对应结果，避免多个工具时错配。共享会话保存消息时锁定会话行，确保并发回复的轮次和时间顺序完整。

## 上下文与人工确认

- 冻结上下文包必须属于本项目；含私人会话来源的资料只能用于私人会话，来源已更新时明确按历史快照解释。
- 私人会话的分支默认继承私人可见范围，避免自动变成共享会话。
- 回复保存前和保存事务内检查可见范围是否变化。模型只能生成待人工确认的草案，不直接创建任务、指派或通过验收；登记资料不代表实际运行代码或验证测试。

## 验证

模拟模型驱动了会话续接、任务上下文、草案生成与审批登记、取消和空回复等场景，另有 API 响应兼容、成员权限、阶段分母、工作量、私人资料隔离及并发消息保存测试。模型测试不调用真实供应商，不宣称已验证真实模型回答质量。

只读查询核对了汪汪队实际的“敏捷开发平台”：当前阶段为“需求澄清与架构基线”，验收 0/9；鱼乐、哈哈哈和聂翔各 14 项未完成任务；郭诗辉为老师，无执行任务；1 项未解决求助。没有改动项目业务数据。

相关 Vitest 12 个文件、60 项通过；生产构建通过；ESLint 0 错误、30 个已有警告。
