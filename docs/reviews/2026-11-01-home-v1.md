# 家园第一版

用户授权新增侧栏“家园”，默认进入自己的家，可布置并保存，队友可访问，另有团队公共庭院。本轮仅增加家园模块及导航接线，不改任务状态、模型配置或项目验收。

## 使用

- `/home`：自己的家，首次访问自动建立，默认允许同团队的人来访。
- 点击“布置家园”：改名字、欢迎语、氛围、访问权限和体验伙伴；添加家具，点选网格、拖动或用方向键移动；可左右翻转、收纳。保存后刷新仍保留；取消放弃当前编辑。
- `/home?view=members&team=<uuid>`：所选团队的成员家园。未开启或设为私有的家园不可访问，成员列表不返回私有家园名称或伙伴资料。
- `/home?view=members&owner=<uuid>&team=<uuid>`：拜访同团队成员。访客只能参观，不能提交主人的布局；所有保存都从认证会话取 ownerId。
- `/home?view=courtyard&team=<uuid>`：共享庭院，支持切换自己的团队。把自己的伙伴送到庭院，或叫回家。庭院的伙伴列表来自数据库，15 秒刷新一次；不是成员在线状态。
- “一起合影”先将当前画面中的伙伴排列集合，再点“保存合影”下载独立 SVG 文件。合影仅保存到本机，不上传或发布。

## 数据与权限

新增 `home_profiles` 一表，开发部署执行 `npm run db:push`，测试库执行 `npm run db:push:test`。本地两库已同步。保存采用 `revision` 条件更新，旧窗口不能覆盖新布局。家具最多 24 件，格位不得重叠，位置和家具类型由服务端校验。

访问家园需要共同团队关系且主人设为开放；庭院需要当前团队成员资格。离队用户即使还保留庭院位置记录，也不进入该庭院的展示名单，可从自己的家召回。伙伴位置只存一个 `pet_team_id`，空值代表在自己家，避免重复出现在多个场景。

布局与宠物位置分开更新，因此布置时另一窗口送伙伴出门，不会被保存布局覆盖。写入接口检查认证和请求来源。Next 内部可能用 localhost 构造 URL，因此来源校验使用本次请求的 Host，而非内部 hostname。

## 桌宠对接边界

仓库当前没有其他成员的自定义桌宠资产、注册接口或桌面同步协议。本版提供小猫、兔子、小狗三种 SVG 体验伙伴，可更名；界面标注“家园体验伙伴”。不能把它们说成已经接通桌面桌宠。

- 数据契约：`src/lib/home-contract.ts` 中 `HomePet`。
- 唯一绘制入口：`src/app/(app)/home/home-art.tsx` 的 `PetAvatar`。
- 后续需与桌宠负责人约定 petId/ownerId、资产路径、帧尺寸、脚底锚点、动画状态和位置同步；扩充契约与绘制适配器即可沿用家园和庭院。
- 当前“打招呼”是当前浏览器的视觉反馈，不是跨客户端通信；庭院没有自主社交、在线追踪、礼物或访客留言。庭院设施为公共固定布置，暂不提供多人装修。

## 视觉统一调整

用户反馈家园与网站整体风格不匹配后，改为复用站点的灰绿阅读面、白色面板、深青文字、绿色主动作和现有圆角/边框/阴影变量。标题使用 `ac-page-header`，区域切换采用分段控件，操作按钮与项目页面一致。移除英文装饰标题和纸纹，增加主要控件的文字尺寸，场景屋顶、墙体、草地和小径改为与站点一致的青绿、灰蓝色。

调整只涉及家园的视图、CSS Module 和 SVG 配色。已验证桌面和手机截图、布局保存、庭院、参观、召回和合影，未改变数据、访问权限或任务流程。
