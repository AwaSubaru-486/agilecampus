# 接着已有成果继续开发

用户确认的路径：继续开发 → 查看变化 → 保存版本。上方仍按已发布版本竖列展示模块，下方由多项必填表改为完整项目模块工作区。

- 基准是同项目已发布版本；新工作区继承模块稳定 ID、能力描述、成果链接、模块备注和整体工作断点。保留未变化模块，仅变化模块进入演进图。
- 旧版只有变化列表，按显式基准递归合并；旧模块同名时沿用身份。不会读取任务或补造代码成果。旧字段和档案保留。
- 修改模块只有名称和能力描述必填，成果链接及备注可选。恢复原描述会取消差异；仅改备注不伪装成功能变化。
- 保存成版本只需确认变化和版本名称；服务端以单事务冻结完整模块快照并生成变化说明。无功能差异时不生成空版本。
- 保存后可直接继续，带上成果和上下文。复制开发上下文含模块现状、前后描述、链接、备注和工作断点。
- 链接代表用户提供的外部成果地址，可能指向可变内容；不等于不可变文件归档。描述对比不是代码差异或实际测试，不自动运行 AI、接入 Git 或回退代码。
- 继承模块暂不提供删除；新增模块可通过新增入口保存。修复与完善在新工作区统一归为在原模块上改进。

数据迁移：`scripts/migrations/2026-11-04-iteration-workspace.sql`，新增 nullable JSONB module_snapshot；dev/test 均已应用。NULL 表示兼容旧变化列表。

权限与一致性：沿用组长写入、成员/老师只读与代理视角；项目事务锁、更新时间冲突校验、同项目基准、版本唯一、HTTP(S)链接校验。历史版本不可修改。重复继续同一基准返回现有开发工作区。
