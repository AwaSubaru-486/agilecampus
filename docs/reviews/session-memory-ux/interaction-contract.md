# 会话区交互与状态契约

范围：VS Code 扩展 H00–H02；只做本机记录，不发布会话文本、不调用模型、不自动交接 Agent。

## 主路径

```text
选择任务 → 关联该工作区的一条 Codex CLI 会话 → 明确启用本机 Hook 记录
        → 在 Codex 审查/信任 Hook → VS Code 查看本地记录
```

“已关联”仅表示工作区、AgileCampus 任务与 Codex session ID 已在扩展私有存储建立绑定。只有 Hook 配置已写入并经 Codex 信任、且至少一条事件确实写入本机事件日志后，界面才显示“已记录”。配置存在但未确认事件时显示“等待 Codex Hook 信任或新事件”。

## 操作到实现与成功证据

| 用户操作 | Host 处理 | 成功证据 | 失败状态 |
| --- | --- | --- | --- |
| 选择任务 | 只设置当前查看任务 ID，不改动任何现有绑定 | 任务详情回执与对应 task ID 一致 | 任务不在当前项目则拒绝 |
| 关联会话 | Entire CLI 列表 → 本机 Quick Pick → 明确同意本机存储 → `LocalSessionStore.bind` | store 返回绑定；Webview 只收到脱敏摘要 | 无 CLI/版本不支持/无可选 session/绑定冲突均显示原位错误 |
| 启用 Codex 记录 | 显示数据范围与配置路径 → 用户确认 → 合并用户级 `hooks.json` → 打开 Codex `/hooks` 审查说明 | 配置文件可解析，已合并指定处理器 | 格式损坏、权限失败或路径无法确认时不覆盖原配置 |
| 查看记录 | 仅在用户主动打开记录面板后读取本地页 | 连续序号、页数和实际事件正文从本机日志返回 | 本地日志/游标/页序损坏时展示错误，不显示为空 |
| 停止此会话记录 | `LocalSessionStore.unbind`，保留原记录 | 后续 Hook 不再匹配 active binding；历史仍可读 | 不删除历史文件、不称为暂停/恢复 |
| 加载更早记录 | 每页最多 50 条，按序号定位，只读取本页正文 | 返回 `hasOlder` 与下页游标 | 不连续的序号使请求失败并提示记录缺口 |

## 采集边界

- Hook 只接受已被本机显式绑定的 Codex `session_id` 与其工作区路径；不匹配则无操作。
- 事件类型：`UserPromptSubmit` 用户输入；`PostToolUse` 工具调用输入和结果；`Stop` 最终助手答复；`SubagentStop` 子 Agent 最终答复。
- 不读取或解析 `transcript_path`；不采集完整模型隐藏推理；不承诺精确恢复内部上下文。
- 事件原文可能包含私密提示、终端输出、密钥或代码内容。只在用户明确同意并在 Codex 审查 Hook 后记录；记录留在 VS Code Global Storage，不上传。
- 单个标准化事件正文上限 256 KiB。超限时写入清楚的 `gap` 事件，不静默截断。
- Hook 入参上限 8 MiB；超限时 Hook 报错，不伪造已记录状态。
- Hook 没有可信源时间戳时事件 `timestamp=null`；本机最新落盘时间单独从文件元数据展示。
- Claude 不显示可用状态或开关，直到 provider adapter、事件 schema 与真实 Host 验证通过。

## 页面状态

| 状态 | 可见文案 | 主动作 |
| --- | --- | --- |
| 未选任务 | 先选择一个项目任务 | 项目任务列表 |
| 未关联 | 未关联 Codex 会话 | 关联会话 |
| 已关联/未启用 | 已关联；本机记录未启用 | 启用记录 |
| 配置已写入/未信任 | 等待 Codex 审查 Hook | 查看 `hooks.json` / 在 Codex 执行 `/hooks` |
| 已启用/暂无事件 | 等待新记录 | 查看记录、检查来源 |
| 有本地事件 | 本机已保存 N 条；最后落盘时间 | 查看记录 |
| 已停止 | 已停止记录；历史保留 | 查看历史 |
| 读取/写入异常 | 给出具体原因 | 重试（仅只读或幂等动作） |

用户级 Hook 的禁用入口不依赖当前任务绑定：Hook 存在时在会话区显示禁用操作，同时命令面板提供「AgileCampus: 禁用本机 Codex Hook」，以便断开项目或换任务后仍能关闭。没有 AgileCampus Hook 时该操作不得改写配置，并明确反馈无变化。

事件读取、会话刷新不清空任务详情缓存。打开记录是单独的 VS Code WebviewPanel。新事件提示不得抢焦点或滚动；用户主动点“查看新记录”才跳到最新。

## 视觉/交互约束

- Direction: Developer Tool / CLI Companion；沿用 VS Code 主题变量与当前字号、间距。
- 侧栏使用一条“会话记录”定义式区域；状态和数字同行，次级动作用文字按钮，分隔用 VS Code 面板边界实线。
- 不增加营销副标题、彩色竖条、虚线框、圆角统计卡、动画录制灯或 emoji。
- 原位显示状态和恢复入口；只读载入少于 1 秒不闪 spinner，耗时操作显示状态；键盘焦点可见。
