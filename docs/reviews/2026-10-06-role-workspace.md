# 三角色工作区：后端检查与前端重构

基线：`feat/risk-aware-closure`，`ff55eda`。本轮在独立的 `codex/role-task-workspace` 分支执行，原有旧副本及未提交改动保持原样。

## 后端检查结论

任务树已有真实数据库、模型调用、草案发布、任务交付与阶段审核。阶段依次推进，追加需求不会删除原有任务。分支、SHA 和测试摘要属于人工登记材料，不会自动执行 Git 合并或 CI；没有完整的版本发布、回滚或燃尽图业务。

本轮修正：

- 导师不能通过底层任务函数认领、提交或登记交付，即使任务被误指派给导师。
- 阶段集成提交收口到组长；组员登记任务交付，组长组织集成，非提交者进行审核。
- 任务树生成的成员名单、草案编辑和发布校验排除导师执行角色。
- 新增组长草案编辑接口，校验项目权限、任务层级、数量和可执行成员，只有 pending 草案能保存；发布使用已保存内容。
- 会话记忆输入校验移除两处可选链后的非空断言，保留原有校验行为。

待后续统一的旧业务规则（本轮不改变兼容接口）：

1. 普通任务网页创建只允许组长，但 `createTask` 和 Agent API 仍允许 student 创建。旧测试明确要求此能力。
2. 普通任务编辑和删除的底层权限仍是 admin/student，尚未统一为组员只能编辑自己负责的任务。新任务树的生成、编辑、发布、交付及集成入口已分别检查权限，但不代表所有旧任务接口已经统一。
3. `/rbac` 使用模拟成员数据，与实际团队角色管理不是同一套数据源；它不能作为真实权限验收依据。
4. 导师评分通过项目反馈标题与正文归档，尚无结构化成绩管理。
5. 新增需求的去重主要由模型提示词控制；真实模型拆解质量尚未实测。

## 前端结果

- 项目入口增加基于真实团队角色的职责与操作引导。
- 任务树重组为阶段导航、验收进度、执行任务列表、交付材料、集成审核和下一轮需求规划。
- 组员可切换“全部任务 / 我的任务”；导师没有生成和交付入口；审核人不能审核自己提交的集成。
- AI 草案可编辑说明、阶段名称、任务名称、描述、负责人、优先级和完成标准。未保存时禁止发布，保存后才开放发布。
- 完成阶段继续显示交付分支、测试摘要和审核意见；未解锁阶段展示原因。
- 表单补充标签、提交中状态与可访问错误反馈；修复侧栏账户菜单向屏幕外展开的问题。
- 页面明确使用“阶段迭代”，没有把未实现的版本发布或自动代码合并包装成可用入口。
