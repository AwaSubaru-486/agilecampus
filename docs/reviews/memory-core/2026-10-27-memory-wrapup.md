# 接续会话收尾

## 本轮功能

任务记忆面板在接续状态为 finished 或 failed 且存在 attemptId 时，提供“整理本次会话为新断点”。链接携带任务和执行记录 ID，不携带原始会话、token 或任意命令。

插件核对已绑定服务、项目和任务，再读取当前工作区对应的本地执行记录。只有 finished/failed、已记录继承来源及 providerSessionId、工作路径匹配的执行，才允许整理。通过本机会话绑定定位准确 sessionKey，交给现有提炼流程；不能唯一定位时拒绝，不能选择其他会话代替。running/unknown 不作为已经结束的执行处理。

仍保留脱敏预览、发送模型确认及逐条审核。审核后，用网页“保存断点”同步已确认材料；不会因打开整理入口而自动发布或启动新 Agent。

另补两个界面细节：插件同步新断点后切到新版本；历史断点列表显示作者和记录编号，避免不同会话同为 r2 时混淆。

## 组内展示顺序

1. 查看任务的旧断点及失败方法。
2. 从网页接续，在插件确认后执行。
3. 会话结束后回网页，点“整理本次会话为新断点”。
4. 插件定位本次会话，预览、提炼并审核记忆。
5. 回网页保存新断点，再与继承版本比较。

这把操作入口串起来，但没有新增“本次收尾已完成”的服务器状态；是否已生成并发布准确的新断点，仍需核对实际材料。真实双机、真实模型完整流程仍待验证。
