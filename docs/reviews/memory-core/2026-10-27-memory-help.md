# 工作断点接入任务求助

## 使用

任务详情 → 当前工作记忆 → 带此断点求助。面板自动带入当前项目、任务及指定断点。

也可以点右下角“任务求助”（原“需要搭手？”），选关联任务和工作断点，再点击“将断点内容追加到说明”。生成说明含进度、阻塞、失败方法、下一步、断点记录 ID 及代码基线，可修改后发送。不会自动邀请成员或启动 Agent。

发送后显示成功反馈，可进入协作中心。协作中心保留自己的未解决求助，标记“我发起的”；展开“求助说明与工作断点”可看已保存说明，任务链接直接进入对应任务。之前这里隐藏自己的求助且不展示 detail，导致发送后难以回查，本轮已修复。

## 实现边界

- 沿用现有求助记录、通知和权限，不新增任务状态或改变验收流程。
- 项目求助列表复用 listOpenBlockersForUser 的项目访问过滤。
- 求助说明保存为可编辑文本快照；它不是新建的强类型记忆关联。断点记录 ID 用来识别来源，接续仍需在任务记忆中选择版本。
- 当前列表最多读取 50 份记忆；指定版本不在列表时提示重新选择，不替换成最新版本。
- 跨项目、切换关联任务清理记忆候选与说明；请求清理阻止旧异步结果覆盖新任务。
- 网页面板保持既有工程工具配色、字体和条目结构，移除求助按钮装饰点和标题下的宣传文字；支持 Escape、关闭后焦点返回、错误重试及发送反馈。

## 验证

32 项定向测试通过：既有求助领域测试、任务记忆视图及新增求助上下文测试。定向 ESLint 和网页生产构建通过。

浏览器在独立测试库实际执行：任务记忆按钮 → 自动带入任务和指定断点 → 追加说明 → 填写帮助需求 → 发送 → 协作中心查看自己发起的求助 → 展开已保存断点。失败方法及下一步在保存后仍可见。证据为 `web-evidence/help-memory-submitted.jpg`。

测试账号、任务、记忆均为合成数据，没有通知真实组员，也未运行真实 Agent。
