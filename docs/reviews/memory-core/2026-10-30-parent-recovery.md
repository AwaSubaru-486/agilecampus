# 精确父版本恢复与历史证据（2026-10-30）

## 解决的问题

0.1.5 的迭代报告只从本机记忆库查找父版本。换电脑后，本机可能只留有子版本；网页历史又只返回最新 50 条。依赖列表无法稳定取得较早的继承来源。

现在复用任务记忆 GET 接口，新增精确引用读取：

`GET /api/projects/:projectId/tasks/:taskId/memory?memoryId=:id&revision=:revision&digest=:sha256`

读取仍要求当前项目成员权限，支持浏览器会话和 PAT；有无效 Bearer 时不退回 Cookie。只读取当前项目、任务中的指定修订，再验证内容摘要。缺失返回 404，摘要冲突返回 409，参数缺失、重复或与 version 混用返回 400。响应沿用 private,no-store，不增加数据库表。

## 插件行为

审核记忆草稿时：

1. 优先使用本机当前账号、工作区、项目、任务范围中已校验的精确父版本。
2. 缺失时，在重新核对当前身份后，向绑定服务请求指定引用。插件再次校验整个接班材料、服务、项目、任务、修订与内容摘要。
3. 只有全部一致才缓存到本机。随后可离线比较这个版本。
4. 网络、权限、版本缺失或校验失败，显示无法比较的说明，仍允许审核当前草稿。选择“查看本轮迭代结果”可重试，不自动改用其他修订。

仅下载项目中已共享的记忆包。此过程不上传当前草稿、原始对话或本机文件。旧父版本只有 ID 没有精确引用时不猜修订。

## 历史摘要不升级为新证据

新提炼输入使用 memory-extract-v3，把插件自己写入的继承 user 事件标为 contextRole=inherited-memory，不传本机 sourceRef。原文本仍保留，以便延续失败条件和约束。普通会话事件不会仅因文本看起来像历史摘要而被自动标记。

模型提示明确这些内容只能作为历史说明；服务端和插件校验器同时拒绝把仅引用历史注入事件的条目标为 captured。reported/inferred 可继续保留历史经验。迭代报告额外标注“仅有继承摘要依据，未验证本轮进展”，避免改写旧完成项后看似产生新成果。

这是明确来源和证据等级的约束，不能验证模型是否理解项目，也不能防止所有语义改写或混合引用错误。仍需人工核对当前代码与实际测试。

v1、v2 请求继续使用原规则，v3 输入会生成不同摘要，避免命中旧提炼缓存。插件 0.1.6 需要配套本批服务端。

## 验证范围

自动化使用合成会话和临时 Git 仓库。服务端测试保存超过 50 个修订，再用成员 PAT 精确取回窗口外的父版本，并检查无效令牌、非成员、其他任务、参数冲突和摘要错误。插件测试模拟空接收端取回、校验并离线复用父版本，检查拒绝替代版本及失败后重试。模型请求测试使用模拟响应，检查 v3 指令与两端证据校验。

插件全套 35 个文件、199 项测试通过。服务端相关 2 文件 19 项通过；最后补充非成员和跨任务断言后，记忆接口所在文件 13 项再次通过。网页生产构建及插件编译、0.1.6 VSIX 打包通过。相关 ESLint 无错误。配套本地服务已重启，登录页 HTTP 200，构建指纹检查 ready。
