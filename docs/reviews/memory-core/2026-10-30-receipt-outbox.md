# 接续回执持久化与恢复（2026-10-30）

## 解决的问题

此前回执只在插件进程内排队。即使最终回复与尝试状态已写入本机，未发送的 running/finished 回执仍可能随插件退出丢失，使网页停留在旧阶段。

本批插件 0.1.7 把网页接续的真实回调先写入 VS Code globalStorage 的 `session-memory/continuation-outbox`，再沿用已有 PAT 接口补传。队列绑定服务、项目、任务、版本、请求、领取凭据、账号及工作区，仅保存状态和引用，不含 PAT、原始对话或代码。

## 顺序与一致性

- 每个请求沿用领取后的原序号，从 2 开始递增。写盘使用临时文件、文件同步及原子重命名，文件权限 0600。
- 磁盘修改与网络发送分别使用已有 Git CAS 协同锁。多窗口只允许一个发送者；网络等待期间仍可写入后续真实回调。
- 服务器确认后才移除队首事件。响应丢失时重发同一序号，复用服务端幂等检查；不跳过旧事件发送后续状态。
- 本机也检查合法阶段、固定 attemptId 和 running 的真实会话标记。补传不会生成新的任务、请求、尝试或 Agent 进程。
- 文件损坏、符号链接、绑定变化、权限撤销或顺序冲突均保留原文件，不覆盖或伪造成功状态。

## 用户入口

在受信任且已连接的 VS Code 工作区中，插件激活后及每 30 秒尝试恢复。只处理该工作区当前绑定项目、当前账号的记录。切换账号时保留旧队列，不能替旧账号上报。

命令面板运行 `AgileCampus: 重试同步接续回执` 可立即重试；结果显示仍待同步的请求数量。自动恢复无弹窗；与手动操作共用防重入。每轮每工作区最多处理 8 个请求；网络故障停止当前工作区本轮发送，后续轮次重试。

网页仍使用已有“当前工作记忆”接续进度，不新增页面或导航。使用 0.1.7 安装包即可；本批没有服务端迁移或任务状态规则修改。

## 不覆盖的情况

该队列只补传已成功观察并写盘的状态。插件在收到最终回调之前退出，不会凭进程消失就宣称成功；应检查原有本地尝试记录。领取成功但插件尚未建立队列就退出，也不在本批恢复范围。

不会恢复已退出的模型进程、备份整个工作区或自动重跑任务。删除扩展 globalStorage 会删除本机待发送记录。持续离线时队列保留，但网页无法获得新状态；本批未实现远端心跳超时判定。

## 验证

临时本机队列测试覆盖断网后保存 running/finished、重新创建实例补传、响应丢失时固定序号、双发送者互斥、慢发送期间追加终态、账号/工作区/服务/项目/领取凭据隔离、伪造会话与坏文件拒绝。命令级测试覆盖切换账号、切换项目、非受信任工作区、离线保留及手动重试。

服务端集成测试通过真实 PAT route 接收合成回执：模拟 running 已被服务器接收但响应连续丢失，创建新的队列实例后补传至 finished，检查数据库事件按序且不重复。会话确认标记为测试合成数据，不代表真实模型执行。

验证结果：插件全套 37 文件、209 项通过；任务记忆与接续接口 14 项通过。根项目和插件 TypeScript 检查、插件编译与 0.1.7 VSIX 打包通过；本次修改的根项目测试文件 ESLint 无错误。网页后端实现未改，现有生产构建指纹仍为 ready，登录页 HTTP 200。

没有进行真实双机、真实 Extension Host 或真实模型完整接班。
