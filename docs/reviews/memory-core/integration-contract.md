# 会话记忆与接班材料集成契约

状态：本机核心代码已实现；跨设备平台传输与 VS Code 实机验证尚未完成。

## 1. 用户可执行入口

VS Code 命令面板提供三条命令：

1. `AgileCampus: 提炼本机会话记忆`：选择已绑定的本机会话，冻结当前事件前缀，在 VS Code 打开展示实际请求 JSON 的脱敏预览；再次确认后，才调用服务端模型。结果保存为本机草稿并进入审核。
2. `AgileCampus: 审核或导出会话记忆`：重新载入草稿及其原始本地快照，逐条查看出处、编辑/删除、补充记忆或测试记录；接受后生成不可变 V1 记忆与接班材料。
3. `AgileCampus: 导入并核对接班记忆`：读取发送者显式选择的 JSON，校验格式与摘要，在当前工作区核验服务、项目、任务权限、Git 仓库身份、HEAD、未提交改动和仓库恢复限制。任何核验失败都只展示阻塞项；通过后，用户可选择将上下文复制给 Codex/Claude。命令不会启动 Agent。

导出 JSON 不加密，也不包含原始 transcript；它包含整理后的工作记忆、项目/任务标识、Git 基线及事件 ID 出处。发送者必须通过可信渠道手动传递，不应提交到公开仓库。接收者不能凭事件 ID 读取发送者电脑上的原始事件。

## 2. 服务端提炼接口

`POST /api/extension/v1/projects/{projectId}/session-memory/extract`

- 使用现有 Personal API Token 的 Bearer 鉴权、项目成员检查和任务归属检查。
- 仅收固定版本的 `PreparedExtractionInputV1`；服务端复核大小、范围、顺序、预算遗漏、完整性、脱敏版本和 `inputDigest`。
- 仅调用现有 `getModel()` 向服务器配置的模型服务发请求；模型没有执行会话中命令、读取本机文件或访问任意 URL 的工具。会话内容按不可信数据处理，输出严格 schema 的记忆候选与 event ID 出处。
- 每个引用必须来自实际发送的事件；`captured` 测试必须有匹配的工具命令/工具结果/非空退出码；口头测试只能标 `reported`。
- 请求正文、prompt、模型响应不写入应用日志或数据库；响应加 `Cache-Control: private, no-store`。模型配置或网络失败返回错误，不造模板结果。
- 扩展端的本机跨进程锁仅防同一输入在该电脑重复发起；不承诺跨电脑/服务端全局 exactly-once。

明确出站限制：原始本机事件文件、provider 原生 session ID、绝对工作区路径、Personal API Token、未提交 diff 不出站。输入最多 500 条事件、正文预算 48 KiB、单事件 8 KiB、请求 JSON 2 MiB；模型输出最长 4000 tokens。已知秘密模式会被替换，但这不是完整 DLP，预览确认不可省略。

## 3. 数据与所有权

| 阶段 | 权威内容 | 保存位置 | 下游可做什么 |
| --- | --- | --- | --- |
| `captured` | 追加式、规范化会话事件 | 当前电脑扩展私有存储 | 本机分页、冻结；不覆盖或删原文 |
| `prepared` | 冻结快照、脱敏输入、遗漏与缺口 | 当前电脑扩展私有存储 | 复核发送内容与来源范围 |
| `candidate` | AI 结构化候选及 evidenceRefs | 当前电脑不可变草稿版本 | 查看原始事件、人工修改/删除/补充 |
| `accepted` | 人工接受后的 strict `MemoryDocumentV1` | 当前电脑不可变记忆版本 | 作为后续迭代的记忆父版本 |
| `material-ready` | 摘要、测试、Git 基线、完整性与出处索引 | 当前电脑私有材料；另可人工导出 JSON | 另一电脑核验并复制上下文 |
| `published/downloaded/agent-started` | **本工单不产生这些状态** | 尚无跨设备平台传输 | 需由其他负责人另行实现并实机验收 |

后续会话若产生新的事件范围，会形成新的 memory ID，并通过 `parentMemoryId` 链接最近的已接受版本；已接受版本本身不可修改。人工编辑与删除标记留在本机草稿谱系中，重提炼不会静默覆盖它们。

## 4. 接收端的阻塞条件

接班上下文只有在以下事实逐项通过后才允许复制：服务与项目匹配；当前 API 身份能读取该任务；本机 Git 仓库身份 hash 与发送者一致；当前 HEAD 与记忆基线一致；工作区无未提交改动；接收版本与 JSON 版本一致；发送材料标记的恢复限制均已处理。未通过时没有“强行继续”按钮。

即便全部通过，接班材料也不能恢复另一提供商隐藏的模型状态、原生 session ID、工具进程或发送端未提交代码。接收者的 Agent 需要自行读取当前代码、核对材料，再由人决定是否继续。

## 5. 队友接口与明确不在本模块的责任

- Worktree 负责人：导入后负责提供实际隔离工作区；不接受本模块创建分支、checkout、合并或提交代码。
- 账号/服务端负责人：现有 Personal Token 与成员权限仍是鉴权依据；私有服务端材料存储、成员可见性及跨电脑下载仍未实现。不要把公共 Git 仓库当私人会话库。
- 前端负责人：可调用 `vscode-extension/src/memory/**` 的纯函数、状态与输出契约接入界面；当前这三条入口在 VS Code 命令面板，未改 Webview 布局。
- 真实来源适配：当前工作区中存在 Codex Hook 的本机记录代码，但本报告未证明真实 Extension Host 的完整捕获；Claude 采集也未实测。接班算法不能补造未捕获的会话内容。

本契约不改变共享 `MemoryDocumentV1`、任务状态、验收、权限或 worktree 语义。
