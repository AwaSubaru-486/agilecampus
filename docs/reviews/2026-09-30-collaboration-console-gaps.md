# 协同执行台后端能力缺口

## 缺口 01：浏览器侧启动 Agent Run 的入口未确认

- 期望动作：用户在任务面板点击后，将一项任务安全排入 Agent 收件箱。
- 找过的文件与接口：`src/lib/agent-run.ts` 的 `enqueueRun`；`src/app/api/agent/runs/route.ts` 仅接收 Agent Bearer 上报。
- 实际缺什么：目前只确认排队函数定义，没有确认给已登录网页用户调用的 server action/API。
- UI 如何避免误导：第一块规则层只有在 `canStartAgentRun=true` 时才显示“开始 Agent”；当前默认能力应为 false。
- 需要谁确认：Codex 核心/后端负责人确认写入口、权限和幂等策略后，另开后端工单。

## 缺口 02：真实运行继续/停止/重试入口未确认

- 期望动作：用户能继续、停止或重跑真实执行器。
- 找过的文件与接口：`agentRuns` 状态和 `reportAgentRun`；未确认浏览器可调用的执行器控制接口。
- 实际缺什么：当前代码能接收 Agent 上报，但不等于网页能恢复进程或控制工作区。
- UI 如何避免误导：只显示查看运行、查看错误、查看证据；不显示继续/停止/重跑。
- 需要谁确认：后端执行器负责人提供真实接口、授权、幂等、并发策略和仓库版本绑定。

## 缺口 03：可恢复 checkpoint 的数据来源未确认

- 期望动作：另一位执行者从明确断点继续并知道已有尝试。
- 找过的文件与接口：`agentRuns.result/error`、activity、messages、context packs。
- 实际缺什么：这些记录可以展示历史，但不自动证明代码工作区可恢复。
- UI 如何避免误导：时间线只称“已记录进展”；分支按钮只称“从此消息创建会话分支”。
- 需要谁确认：执行器负责人定义代码版本、工作区、已运行命令和验证结果的持久化协议。
