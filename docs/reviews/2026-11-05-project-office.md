# 项目办公室与看板合并

按用户要求将独立家园合入每个项目。项目默认首页由 MemberBoard 替换为 ProjectOffice，导航首项改为“办公室”；全局家园入口移除，旧 `/home` 转到项目选择。组长“项目推进台”、老师“导师审核台”和任务、分工、验收入口保留。

办公室沿用背景、工位、打字动画和按需桌宠抽屉。墙上的任务黑板为有焦点提示的可访问按钮，点击打开原生 dialog：复用 MemberBoard 的真实任务树和协作求助数据，默认展开阶段，仅显示当前项目中分配给当前视角用户的非任务组任务。点击任务仍进入原执行页面，未替换任务状态机、动作 API 或任务记忆链路。角色预览仍使用 viewUserId 读取任务，办公室的桌宠写操作在预览时禁用。

新增 `home_profiles.working_project_id`，开工时核验项目可访问且属于指定团队，按项目过滤在座状态。同一人同时只声明在一个项目工作；结束清空工作项目，重新选择桌宠也清空。原团队开工记录没有补造项目 ID，因此不会自动出现在某个项目办公室里。团队成员身份仍沿用项目现有访问模型，不另设成员权限。

部署先执行 `scripts/migrations/2026-11-05-project-office.sql`；本机开发、测试数据库已应用。本地 3000 服务已更新。

验证：家园与 API 三个文件共 23 项测试通过；角色、项目视角及导航归一化回归通过；生产构建通过且运行指纹 ready；全站 lint 0 错误、30 条原有警告。真实浏览器使用临时团队、两个项目和分别分配的任务，验证黑板弹窗、按项目与负责人过滤、原任务链接、开工隔离、组长/老师入口、手机弹窗与旧入口跳转，结束后清理测试数据。脚本 `.local/verify-project-office.cjs`，截图 `.local/project-office-scene.png`、`.local/project-office-tasks.png`。

桌宠自定义来源仍沿用 HomePetProvider。旧桌面客户端的“打开家园”链接会经 `/home` 进入项目选择。
