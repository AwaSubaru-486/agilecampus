# 家园场景与桌宠接口调整

用户明确指出简笔画与平台风格冲突，并要求为队友后续的自定义桌宠功能保留易合并的接口。

## 结果

- 移除手绘小屋、曲线浮岛、装饰云朵及内置猫/兔/狗。场景改为规则建筑空间、网格地面、玻璃墙面和模块化设施；沿用平台白色、灰蓝、深青与绿色控件。
- 桌宠模块独立于家园场景，分为共享契约、服务端来源适配器、归属校验、通用显示组件。支持静态图片与规则精灵图的 idle/greet 动作，支持减少动画和图片失败占位。
- GET/PUT `/api/home/pets` 提供本人可选列表与选择/清空操作。只保存 petId，不允许通过布局保存伪造关联或外观。
- 未接入时提供空列表与中性占位，不伪造已创建的自定义桌宠。未绑定/已删除桌宠不显示在庭院，也不能进入庭院；仍允许召回。
- 同源资源在合影中内嵌保存，避免下载后的相对资源地址失效。

## 合并入口

队友实现 `src/lib/pets/home-pet-source.ts` 的 listOwned(ownerId) 和 getOwned(ownerId, petId)。资源契约、HTTP 返回和边界见 [接入说明](../design/home-pet-integration.md)。无需改动家园布局表、任务流程或现有数据库；不要求队友采用家园定义的桌宠创建表。

现有 home_profiles.pet JSON 兼容旧 kind/name，渲染不再依赖这些内置种类。旧家具 ID 和坐标保持原样，只换显示名称与造型。

## 验证

- 5 个测试文件、29 项通过，覆盖布局权限、旧记录、绑定所有权、精确 ID、跨站拦截、资源地址/编码路径、图集边界、动作渲染、失效资源与召回。
- 浏览器使用临时成员验证保存、取消、刷新、参观、未接入状态、未拥有资源拒绝、合影下载与 390px 手机无横向溢出，结束后清理临时数据。
- 正式构建、TypeScript 与修改文件 ESLint 通过。

本轮没有接入真实队友桌宠资产；资源查询默认空实现，静态图和精灵图通过契约/渲染测试验证。桌面进程同步、自主行为和上传不在本轮范围。用户提供的交付包仅从本地 TypeScript 检查中排除，没有修改或合入。
