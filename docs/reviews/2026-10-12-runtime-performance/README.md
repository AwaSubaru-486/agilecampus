# 本机运行性能优化

2026-10-12，用户授权按诊断结果优化运行方式，保留现有页面布局与功能。

## 结果

- 当前 `http://127.0.0.1:3106` 已切换到 standalone 正式运行模式。源码未变化时，启动器复用编译产物及现有进程；源码或生产环境文件变化后先重新构建。
- `npm run dev` 和启动器的开发模式使用 Turbopack，保留 `dev:webpack` 兼容入口。
- `npm run build` 补齐 standalone 的 static/public 资源，记录内容指纹与 BUILD_ID。过期或被替换的构建不能直接启动。
- Windows 启动器以互斥锁避免重复启动，按进程所属绝对路径保护其他应用；替换当前项目的服务时停止旧服务及其启动进程。
- 工作区外原有 `start-agilecampus.ps1/.cmd` 已修复为调用当前项目的启动器。数据库沿用现有配置，未执行初始化或迁移。

## 实测

之前 Webpack 开发服务主进程约 4416 MiB，另有约 8 MiB 的启动进程。正式模式检查看板与求助详情后的主进程约 127 MiB、启动进程约 51 MiB，合计约 178 MiB。系统可用内存从诊断时约 1.7 GiB 增至检查时约 4.93 GiB。这是本机当次快照，并非内存上限承诺。

历史开发日志中，教程首次访问 7.3 秒（Next.js 7.1 秒，应用 154 毫秒）；切换 Turbopack 后重启服务首次访问 3.4 秒（Next.js 2.8 秒，应用 573 毫秒）。正式模式没有页面现场编译。登录页三次本机 HTTP 检查为 79、6、2 毫秒，均返回 200；这组数据是预热后的未登录页请求，不能直接等同于带登录状态的教程加载耗时。

## 使用

日常双击 `start-local.cmd`，或工作区的 `start-agilecampus.cmd`。修改代码需要热更新时运行 `npm run local -- -Mode development`；切回日常模式运行 `npm run local`。启动器将根据源码内容自动判断是否需要重新编译，强制重编译可加 `-Rebuild`。
